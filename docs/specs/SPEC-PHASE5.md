# Tonus — ТЗ фаза 5: анализы, чат-виджет и трекинг препаратов

Продолжение `SPEC.md`, `SPEC-HUB.md`, `SPEC-PHASE3.md`, `SPEC-PHASE4.md`. Фазы 1–4 реализованы. Здесь — отдельная вкладка для загрузки медицинских анализов, чат с Gemini в контексте всех данных и анализов (виджет, как у онлайн-поддержки), и учёт приёма саплементов/препаратов.

---

## 0. Что нового

- Отдельная вкладка «Анализы»: загрузка и хранение результатов анализов (PDF/фото).
- Чат с Gemini в контексте статистики и анализов за выбранный период — в виде виджета справа внизу.
- Учёт приёма саплементов и препаратов (финастерид, дутастерид и др.) дневной галочкой, с помесячным отображением.

## 1. Вкладка «Анализы»

- Загрузка файлов анализов: PDF и фото (скан/снимок бланка).
- Хранение в Supabase Storage, **зашифрованно, регион ЕС** (самая чувствительная категория данных).
- Извлечение текста из файла (для PDF — текст; для фото/сканов — OCR), чтобы содержимое было доступно ИИ-чату как контекст.
- Список загруженных анализов с датой, типом и возможностью просмотра/удаления.
- **Рекомендуется (сильно повышает пользу):** извлекать из анализов ключевые показатели (например, тестостерон, холестерин, глюкоза, ферритин и т.п.) в структурированную таблицу `lab_results` и строить по ним **тренд во времени** — как меняются биомаркеры от анализа к анализу.

## 2. Чат с Gemini (виджет)

### Поведение
- Плашка-кнопка справа внизу на всех экранах (паттерн онлайн-поддержки). Клик — открывается небольшое окно чата; можно свернуть.
- В шапке чата — выбор периода данных (за какой диапазон дат брать статистику) и, опционально, что включать (анализы / сон / события и т.д.).
- Переписка сохраняется в БД: можно вернуться к прошлым диалогам.

### Контекст
- Чат отвечает, опираясь на: дайджест статистики за выбранный период (как в фазе 4) + ключевые точки из загруженных анализов + события/саплементы.
- Дата-фильтр в шапке управляет тем, какие данные попадают в контекст (и заодно держит объём под контролем).

### Контроль токенов (важно)
- При **открытии сессии** сервер один раз собирает компактный «снимок контекста» (агрегаты + ключевые точки анализов). Он переиспользуется, а не пересобирается на каждое сообщение.
- На **каждое сообщение** в модель уходит: снимок контекста + краткая выжимка предыдущих реплик (rolling summary) + последние 2–3 сообщения + новый вопрос. Не вся история и не сырые данные.
- После N реплик старые сообщения сворачиваются в короткую выжимку, чтобы контекст не рос.
- Для чата — модель подешевле; тяжёлую модель использовать только для месячного глубокого саммери (фаза 4).
- Ограничение длины ответа; опционально — индикатор расхода/мягкий лимит.
- Сохранение переписки в БД дешёвое; дорого только отправлять в модель — экономим на отправке, а не на хранении.

### Рамка безопасности
- Только наблюдения и общая информация, без медицинских диагнозов.
- При тревожных значениях в анализах — мягко направлять к врачу.
- Не выдумывать данные, которых нет в контексте.

## 3. Учёт саплементов и препаратов

- Список препаратов/добавок пользователя: название, дозировка, единица (например, финастерид 1 мг, дутастерид 0.5 мг, витамин D и т.д.). Можно добавлять произвольные.
- Ввод: за каждый день — **галочка «принял»** для каждого препарата (опционально доза и время, если отличаются от обычной).
- Отображение: **помесячная сетка** (календарь) по каждому препарату — какие дни отмечены; процент соблюдения за месяц.
- Данные доступны ИИ-чату как контекст и движку корреляций (например, связь приёма с показателями).
- Опционально (рекомендую): напоминания о приёме.

## 4. Модель данных (дополнения)

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `lab_files` | загруженные анализы | user_id, file_path (зашифр.), date, type, extracted_text, created_at |
| `lab_results` | извлечённые показатели для трендов | user_id, lab_file_id, marker, value, unit, date |
| `chat_sessions` | сессии чата | user_id, period_start, period_end, created_at, context_snapshot |
| `chat_messages` | сообщения | user_id, session_id, role, content, created_at, tokens_used |
| `supplements` | справочник препаратов пользователя | user_id, name, default_dose, unit, active |
| `supplement_logs` | приём по дням | user_id, supplement_id, date, taken, dose, note |

Все таблицы под RLS (`user_id = auth.uid()`).

## 5. Приватность и безопасность

- Анализы и медданные — самая чувствительная категория: шифрование в покое и при передаче, хранение в ЕС (GDPR), строгий RLS.
- Отправка содержимого анализов во внешний ИИ (Gemini) — только с **явного согласия** пользователя (отдельный экран), и только нужный минимум (выжимка, а не весь файл, где это возможно).
- Возможность удалить любой анализ, переписку и весь аккаунт.
- Текст-пояснение в чате и на вкладке анализов: что и куда отправляется.

## 6. Дополнительно (включено в объём)

Эти пункты приняты как часть фазы, а не как опции:

- **Тренды биомаркеров** из анализов (раздел 1) — наглядные графики «как менялся показатель X». Особенно осмысленно на фоне приёма препаратов.
- **Подготовка к визиту врача**: сгенерировать из анализов + статистики краткий PDF-отчёт за период.
- **Напоминания** о приёме препаратов и о повторной сдаче анализов.
- **Связка в инсайтах**: «с начала приёма X показатель Y изменился так-то» (как наблюдение, не вывод о причинности).
- **Дешёвый и дорогой режим модели**: быстрый чат на лёгкой модели, глубокий месячный разбор — на тяжёлой.

## 7. Этапы

- **5a:** вкладка «Анализы» — загрузка, хранение (шифр., ЕС), извлечение текста/OCR.
- **5b:** чат-виджет с контролем токенов (снимок контекста + rolling summary) и сохранением переписок.
- **5c:** трекинг саплементов — список, дневная галочка, помесячная сетка, процент соблюдения.
- **5d:** тренды биомаркеров из анализов; напоминания; отчёт «для врача».

## 8. Принятые решения

1. Из анализов извлекаем ключевые показатели для трендов, а не только храним файлы. **Решено: да.**
2. Чат: снимок контекста + выжимка истории + лёгкая модель для чата. **Решено: да.**
3. Саплементы — дневная галочка + помесячная сетка с процентом соблюдения. **Решено: да.**
4. Явное согласие на отправку анализов во внешний ИИ. **Решено: да, обязательно.**
