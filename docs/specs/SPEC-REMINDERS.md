# Tonus — ТЗ: напоминания о приёме препаратов (сайт + Telegram)

Соединяет учёт препаратов (`SPEC-PHASE5.md`) и Telegram-бот (`SPEC-PHASE7.md`, `SPEC-BOT.md`). Пользователь настраивает напоминания на сайте, бот присылает уведомление с кнопками, отметка о приёме синхронизируется с сайтом.

---

## 0. Сценарий

1. На сайте в настройках препарата пользователь задаёт время напоминаний (например, финастерид — 22:00 ежедневно).
2. В нужное время в Telegram приходит уведомление: «Прими финастерид» с кнопками: **Принял ✓**, **Напомнить через 1 час**, **Напомнить через 2 часа**.
3. Нажал «Принял» → на сайте за этот день проставляется галочка (в модуле «Препараты»).
4. Нажал «напомнить» → бот повторит позже.

## 1. Настройка на сайте

- У каждого препарата (из `supplements`, фаза 5) — расписание напоминаний: время(на) приёма, дни недели, часовой пояс, вкл/выкл.
- Опции snooze (через сколько повторять) — по умолчанию 1 и 2 часа, настраиваемо.
- Тихие часы: интервал, когда напоминания не приходят (например, не позже 23:30).
- Можно несколько препаратов с разным временем.

## 2. Доставка напоминания

- Планировщик (Supabase pg_cron или периодическая функция) проверяет, какие дозы наступили, и шлёт уведомление в Telegram на привязанный чат (`telegram_links`, фаза 7).
- Сообщение с inline-кнопками: «Принял ✓», «Напомнить через 1 час», «Напомнить через 2 часа», «Пропустить сегодня».
- Текст человеческий: «Пора принять финастерид 💊».

## 3. Обработка кнопок (webhook бота)

- **Принял ✓** → записать приём в `supplement_logs` (taken=true, дата, время) за сегодня; подтвердить в чате; отменить отложенные напоминания по этой дозе.
- **Напомнить через 1ч / 2ч** → перенести (snooze) одноразовое напоминание на указанный срок; учесть тихие часы.
- **Пропустить сегодня** → пометить дозу как пропущенную (skipped), не таскать повторами.

## 4. Двусторонняя синхронизация

- Отметка «принял» в Telegram и галочка на сайте — **одно состояние** (`supplement_logs`).
- Если отмечено на сайте — бот в этот день по этой дозе не напоминает (ожидающее напоминание отменяется).
- Если отмечено в Telegram — на сайте сразу появляется галочка за день.

## 5. Границы и честность данных

- **Предел повторов.** Snooze не бесконечен: ограниченное число переносов и/или дедлайн на день; после — доза считается пропущенной, без дальнейшего нытья.
- **Различать «не принял» и «не ответил».** Пустой ответ к концу дня — это «нет данных»/пропущено, а не молча «принято». Важно для честного процента соблюдения (фаза 5).
- **Тихие часы** соблюдаются и при snooze (не переносить на ночь — отложить до утра или пометить пропуск, по настройке).
- Идемпотентность: одно напоминание на одну дозу; повторная отметка не задваивает запись.

## 6. Модель данных (дополнения)

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `reminder_settings` | расписание напоминаний по препарату | user_id, supplement_id, times (json), weekdays, timezone, snooze_options, quiet_hours, enabled |
| `reminder_events` | конкретные дозы и их статус | user_id, supplement_id, due_at, status (pending/taken/snoozed/skipped/missed), snooze_until, responded_at, channel |

Отметка приёма пишется в существующую `supplement_logs` (фаза 5); `reminder_events` — для управления доставкой и повторами. Все таблицы под RLS.

## 7. Забота о пользователе

- Напоминания о приёме — полезная и низкорисковая функция, но не должны превращаться в навязчивость: ограниченные повторы, тихие часы, лёгкое отключение.
- Тон — спокойный и поддерживающий, без давления.

## 8. Этапы

- **R1:** настройка расписания напоминаний на сайте (время, дни, тихие часы) по препаратам.
- **R2:** планировщик + отправка уведомления в Telegram с кнопками.
- **R3:** обработка кнопок (принял / snooze / пропустить) и запись в `supplement_logs`.
- **R4:** двусторонняя синхронизация и отмена ожидающих напоминаний; пределы повторов и тихие часы.

## 9. Принятые решения

1. Расписание настраивается на сайте по каждому препарату; отметка приёма синхронизируется с Telegram в обе стороны. **Решено: да.**
2. Кнопки: Принял / Напомнить через 1–2 часа / Пропустить; snooze с пределом и тихими часами. **Решено: да.**
3. «Не ответил» ≠ «принял» — для честного процента соблюдения. **Решено: да.**
4. Состояние приёма едино (`supplement_logs`); идемпотентность, без задвоения. **Решено: да.**
