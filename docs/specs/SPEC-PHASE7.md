# Tonus — ТЗ фаза 7: автоотчёт раз в 2 недели и Telegram-бот

Продолжение `SPEC.md` … `SPEC-PHASE6.md`. Здесь — автоматический анализ всех показателей раз в 2 недели со сравнением с прошлым периодом, автодоставка отчёта в Telegram и управление через бота.

## 0. Что нового

- Автоматический анализ раз в 2 недели: что улучшилось, что просело относительно прошлых двух недель, короткие советы.
- Отчёт автоматически уходит в Telegram (бот).
- Управление из Telegram-бота: запросить отчёт сейчас, посмотреть прошлый, настройки, пауза.

Движок анализа — тот же, что в фазе 4 (дайджест + сравнение с предыдущим периодом). Новое здесь — расписание, доставка в Telegram и управление ботом.

## 1. Автоанализ раз в 2 недели

- Окно: последние 14 дней vs предыдущие 14 дней, по всем показателям.
- Выход — короткий структурированный отчёт: общий вывод, «стало лучше» (по показателям с дельтой), «просело», 1–2 совета.
- Тон — как в примере пользователя: «за эти 2 недели просел по сну, но по активности норм». Конкретно, по личным трендам, без диагнозов.
- Привязка к дню недели и часовому поясу пользователя (например, каждый второй понедельник в 9:00 по местному).

## 2. Расписание (scheduler)

- Вариант A (рекомендуется): Supabase **pg_cron** запускает edge-функцию по графику.
- Вариант B: **Vercel Cron** дёргает API-роут по графику.
- Функция: собирает дайджест за оба периода → один запрос в модель → формирует отчёт → отправляет в Telegram → сохраняет в БД.
- Идемпотентность: отмечать отправленные отчёты, чтобы не задвоить при повторном срабатывании.

## 3. Свежесть данных (важно)

Данные Apple Health обновляются только при ручной загрузке `export.xml`. Поэтому:

- Перед формированием отчёта функция проверяет дату последней синхронизации (`imports.last_synced_at`).
- Если данные несвежие (например, старше N дней) — бот **сначала присылает напоминание** «залей свежий экспорт», а не считает по устаревшим данным.
- В самом отчёте — пометка, по какой период данные актуальны, если есть пробелы.

## 4. Telegram-бот

### Настройка
- Создать бота через BotFather, получить токен. **Токен хранится на сервере**, не в браузере.
- Бот работает через **webhook**: Telegram шлёт апдейты на серверную функцию (edge function), она обрабатывает команды.
- Вебхук защищён секретом, чтобы принимать запросы только от Telegram.

### Привязка аккаунта
- Чтобы бот знал, кому слать, нужно связать Telegram-чат с аккаунтом Tonus.
- Поток: в приложении пользователь жмёт «Подключить Telegram» → получает ссылку/код для бота → пишет боту `/start <код>` → сервер сохраняет `telegram_chat_id` у этого пользователя.
- Бот отвечает только привязанным пользователям.

### Отправка отчётов
- Сервер вызывает Telegram Bot API `sendMessage` с текстом отчёта на сохранённый `chat_id`.
- Формат — компактный, читаемый в мессенджере (короткие блоки, без «простыни»).

### Команды управления
- `/report` — сгенерировать и прислать отчёт сейчас (с rate-limit).
- `/last` — прислать последний отчёт.
- `/settings` — частота, день/время, что включать.
- `/pause` и `/resume` — приостановить/возобновить автоотчёты.
- `/sync` — напомнить, как залить свежий экспорт; показать дату последней синхронизации.
- `/help` — список команд.

## 5. Модель данных (дополнения)

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `telegram_links` | привязка Telegram к аккаунту | user_id, telegram_chat_id, linked_at, status |
| `scheduled_reports` | история автоотчётов и доставки | user_id, period_start, period_end, content, created_at, delivered_at, channel |
| `report_settings` | настройки расписания | user_id, frequency_days (14), weekday, time, timezone, include_scopes, paused |

Все таблицы под RLS. Автоотчёты можно переиспользовать из `ai_analyses` (фаза 4) + флаг доставки, если не хочется отдельной таблицы.

## 6. Приватность и безопасность

- Сообщения боту в Telegram **не end-to-end шифрованные** — идут через серверы Telegram. Пользователя надо об этом честно предупредить при подключении.
- По умолчанию в Telegram уходит только сводка самочувствия (тренды сна/активности/пульса). **Анализы и приём препаратов в автоотчёт не включаются**, если пользователь явно не разрешил.
- Токен бота и `chat_id` — серверно; вебхук с проверкой секрета.
- Отключение Telegram — удаление привязки и токена доступа; пользователь может в любой момент отписаться.

## 7. Токены и стоимость

- Раз в 2 недели = предсказуемо и дёшево (один анализ за период).
- Дайджест компактный (как в фазе 4); `/report` по запросу — с ограничением частоты, чтобы не злоупотреблять.

- **7b:** Telegram-бот: создание, webhook, привязка аккаунта, отправка отчёта.
- **7c:** расписание (pg_cron/Vercel Cron) + проверка свежести данных + напоминания о синхронизации.
