# Tonus — ТЗ: Отчёт для врача (печатная страница → PDF)

Одна кнопка «Подготовить к приёму» → печатная страница со сводкой здоровья →
браузерное «Сохранить как PDF». Врач получает факты в привычном виде вместо
пересказа по памяти на приёме.

Переиспользует готовое: метрики `daily_metrics`/`daily_scores`, лабы
`lab_results` с реф-диапазонами (`labs.ts`), добавки `supplements`, проблемы
`concerns` (+ PIN-приватность `privacy.ts`), переводы `i18n.tsx`,
Gemini-паттерн `analyze-health`.

---

## 0. Цель

Полный, честный и **консервативный** документ: измеренные значения, динамика,
принимаемые добавки, отклонения в анализах. ИИ — только в отдельном, явно
помеченном блоке «вопросы для обсуждения», без диагнозов и интерпретаций
(решение пользователя, 2026-07-12: print-страница, факты + ИИ-блок вопросов).

## 1. Принципы

- **Врач доверяет цифрам, не выводам** — тело отчёта только из данных;
  всё сгенерированное ИИ визуально отделено и подписано.
- **Пациент контролирует содержимое** — перед печатью выбор секций
  чекбоксами; приватные проблемы (за PIN) исключены по умолчанию.
- **Печать — первоклассный формат** — вёрстка под A4 (`@media print`),
  без интерактива, кириллица нативно, номера страниц.

## 2. Компоненты

### 2.1 Экран подготовки

Точка входа: кнопка «Отчёт для врача» в Настройках (рядом с существующим
экспортом данных). Экран подготовки:

- Период: 30 / 90 / 365 дней (по умолчанию 90).
- Чекбоксы секций: метрики, анализы, добавки, проблемы, ИИ-вопросы.
  Приватные `concerns` появляются в списке только после ввода PIN
  (существующий механизм `privacy.ts`) и по умолчанию выключены.
- Язык отчёта: ru / en (переключатель; словарь — существующий `i18n`).
- Кнопка «Сформировать» → печатное представление → системный диалог печати
  (`window.print()`).

### 2.2 Печатное представление

Отдельный полноэкранный вид (не новый роут — паттерн модальных экранов
приложения), стилизованный под документ:

1. **Шапка** — «Сводка данных здоровья», период, дата формирования, приложение
   как источник, дисклеймер «данные носимых устройств, не мед. измерения».
2. **Метрики за период** — таблица: RHR, HRV, сон, шаги, вес — среднее /
   мин / макс за период + сравнение с личным базлайном. Ниже — понедельная
   таблица динамики (печать дружит с таблицами лучше, чем с графиками).
3. **Анализы** — последнее значение каждого биомаркера из `lab_results`:
   значение, реф-диапазон, флаг ↑/↓ вне диапазона, дата сдачи. Отклонения
   визуально выделены. Если есть предыдущее значение — дельта.
4. **Добавки и приём** — активные `supplements` с дозами и длительностью
   приёма; соблюдение за период (из `supplement_logs`, %).
5. **Проблемы** — выбранные `concerns` с датами начала и статусом.
6. **Вопросы для обсуждения (ИИ)** — см. §2.3; блок в рамке с подписью
   «Сгенерировано ИИ-ассистентом, не является мед. рекомендацией».

`@media print`: скрыть чекбоксы/кнопки/навигацию приложения, A4-поля,
`break-inside: avoid` для таблиц, шрифт из системной гарнитуры.

### 2.3 ИИ-блок «вопросы врачу» — расширение `analyze-health`

Новый режим существующей функции (`mode: 'doctor-questions'`): по тому же
серверному контексту (`_shared/healthContext.ts`) Gemini формулирует
3–5 нейтральных вопросов пациента врачу («стоит ли пересдать ферритин с
учётом динамики?»). Жёсткие рамки промпта: только вопросы, без диагнозов,
без рекомендаций препаратов. `ai_usage.source = 'doctor-report'`. Бюджет —
общий механизм `checkBudget`.

Блок опционален: не выбран чекбоксом → ИИ не вызывается вовсе.

## 3. Данные

Новых таблиц нет. Чтение: `daily_metrics`, `daily_scores`, `lab_results`,
`supplements`, `supplement_logs`, `concerns`. Запись: только `ai_usage`.

## 4. Критерии приёмки

1. «Сформировать» с дефолтами → печатное представление со всеми секциями,
   `window.print()` открывается, макет A4 без обрезанных таблиц.
2. Приватные проблемы не попадают в отчёт без PIN и явного выбора.
3. Биомаркер вне реф-диапазона помечен флагом; в норме — без флага.
4. Отчёт на en полностью переведён (никакого смешения языков).
5. Без чекбокса «ИИ-вопросы» отчёт формируется без единого ИИ-вызова.
6. Демо-режим: отчёт собирается на фикстурных данных (стенд для скриншотов).

## 5. Вне скоупа

Генерация PDF-файла кодом (jsPDF/pdfmake), отправка отчёта в Telegram,
язык de, графики в печатной версии, экспорт в HL7/FHIR, электронная подпись.
