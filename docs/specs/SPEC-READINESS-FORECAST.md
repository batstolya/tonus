# Tonus — ТЗ: Прогноз readiness на завтра

Вечером пользователь узнаёт, каким **завтра** будет восстановление, и почему —
до того, как решит, во сколько лечь и планировать ли тяжёлую тренировку.
Сейчас readiness считается только по факту (`daily_scores`), постфактум.

Переиспользует готовое: скоры и базлайны `daily_scores`
(`hrv_baseline`, `sleep_baseline` и формулы `scores.ts`), события
`intake_events` (кофе/алкоголь/тренировки), среду `environment_daily`
(`kp_index`), вечернее сообщение `send-reminders` (§4).

---

## 0. Цель

Детерминированный, объяснимый прогноз (решение пользователя, 2026-07-12):
балл 0–100 + топ-факторы «почему» + одна рекомендация. Без ИИ-вызовов —
бесплатно, тестируемо, воспроизводимо.

## 1. Принципы

- **Объяснимость важнее точности** — каждый пункт прогноза сводится к фразе
  «−N: три ночи недосыпа». Никакой магии.
- **Личная норма, не популяционная** — все отклонения считаются от базлайнов
  пользователя из `daily_scores`, как в остальном приложении.
- **Прогноз — это ожидание, не приговор** — формулировки вероятностные
  («скорее всего», «есть риск»), без категоричности.

## 2. Модель

Чистая функция `forecastReadiness(inputs) → { score, factors, advice }`.

**База:** взвешенное среднее readiness за последние 3 дня (свежий день — вес
больше: 0.5/0.3/0.2). Нет readiness за 3 дня → прогноз не строится
(«недостаточно данных»).

**Поправки** (каждая — элемент `factors` с величиной и человекочитаемой
причиной; величины — стартовые константы, уточняются бэктестом):

| Фактор | Условие (данные «сегодня» на момент вечера) | Поправка |
|---|---|---|
| Долг сна | средний сон за 3 дня < `sleep_baseline` − 1 ч | −10 |
| Алкоголь | событие `alcohol` сегодня | −15 |
| Поздний кофе | событие `coffee` после 18:00 локального времени | −5 |
| Тяжёлый день | `exerciseMinutes` сегодня ≥ 60 и readiness сегодня < 70 | −8 |
| Магнитная буря | `kp_index` сегодня ≥ 5 (прокси на завтра) | −5 |
| Восходящий тренд | readiness рос 3 дня подряд | +5 |

Итог зажимается в 0–100. `advice` — одна строка по худшему фактору
(«ляг сегодня до 23:00», «завтра лучше без интервалов — лёгкая зона»).
Прогнозного Kp на завтра в конвейере пока нет — используется сегодняшний
как прокси (буря обычно длится 1–3 дня); честный прогнозный Kp — вне скоупа.

## 3. Компоненты

### 3.1 Движок — `src/lib/forecast.ts` + `_shared/forecast.ts`

Зеркальные копии чистой функции (политика `scores.ts`), **parity-тест
обязателен**. Юнит-тесты: каждая поправка отдельно, границы (нет данных,
все факторы разом, зажим в 0–100).

### 3.2 Вечернее сообщение — `send-reminders` §4

К вечернему вопросу «как прошёл день» добавляется блок прогноза (одно
сообщение, не два):

```
Как прошёл твой день? 🌙
Оцени самочувствие 1–5: [1][2][3][4][5]

🔮 Завтра: восстановление ~62 (ниже твоей нормы)
• три ночи недосыпа (−10)
• кофе после 18:00 (−5)
Совет: ляг сегодня до 23:00.
```

Прогноз не строится (мало данных) → блок просто не добавляется, вопрос
уходит как раньше.

### 3.3 Карточка на дашборде

Карточка «Завтра» рядом с текущим readiness: балл, стрелка тренда
(выше/ниже сегодняшнего), факторы по тапу (раскрывающийся список — паттерн
существующих карточек Dashboard). Считается на клиенте из уже загруженных
данных — новых запросов нет. В демо-режиме работает на фикстурах
(`demoFixture.ts` уже содержит события и скоры).

### 3.4 Бэктест — `scripts/forecast-backtest.ts`

Оффлайн-скрипт (vitest-тест на фикстурах + запуск на своём JSON-экспорте
через `exportAllJSON`): для каждого дня истории строит прогноз по данным
«до вечера» и сравнивает с фактическим readiness назавтра. Выводит MAE и
долю попаданий ±10. Скрипт — инструмент калибровки констант таблицы §2,
не продакшн-код.

## 4. Данные

Новых таблиц и колонок нет. Всё читается из `daily_scores`, `daily_metrics`,
`intake_events`, `environment_daily`.

## 5. Критерии приёмки

1. Parity-тест двух копий движка зелёный; юнит-тесты всех поправок зелёные.
2. Вечернее сообщение содержит блок прогноза с факторами; при нехватке
   данных блока нет, вопрос не ломается.
3. Карточка «Завтра» на дашборде: балл + факторы, работает в демо-режиме.
4. Бэктест-скрипт запускается и печатает MAE (порог качества не фиксируем —
   это калибровочный инструмент).
5. Прогноз никогда не выходит за 0–100 и не строится из < 3 дней данных.

## 6. Вне скоупа

ML-модели, прогнозный Kp с GFZ, учёт погоды на завтра, прогноз на 2+ дня
вперёд, генерация текста прогноза через Gemini.
