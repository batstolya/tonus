# Tonus — ТЗ: авто-синхронизация Apple Health (без ручного ZIP)

Убрать цепочку «экспорт ZIP → ноутбук → загрузка». Заменить на:

```
Apple Health → Health Auto Export (по расписанию)
   → POST JSON → Supabase Edge Function `ingest-health`
   → STAGING → (проверка паритета) → боевые таблицы
```

## 0. Главный принцип — НЕ СЛОМАТЬ существующее
Текущая загрузка (Web Worker, парсинг `export.xml`, дедуп) и таблицы
`metrics_daily` / `sleep_sessions` работают хорошо. Новый путь:
- **полностью изолирован** — отдельная функция, отдельные staging-таблицы;
- **по умолчанию ничего не пишет в боевые таблицы** (режим `shadow`);
- в боевые таблицы попадает только после **ручного подтверждения паритета**;
- старый способ загрузки остаётся как есть и продолжает работать параллельно.

## 1. Режимы (feature flag на пользователя)
`ingest_tokens.mode`:
- **shadow** (по умолчанию) — данные пишутся ТОЛЬКО в staging. Боевые таблицы не трогаются. Можно сравнивать.
- **live** — после проверки: данные промоутятся в боевые таблицы через тот же upsert с unique-констрейнтами (повторы не задваивают).

Переключение shadow→live — осознанное действие в Настройках, не автоматическое.

## 2. Данные

### 2.1 Токены
```sql
ingest_tokens (
  user_id uuid, token text unique, mode text default 'shadow',
  created_at, last_ingest_at, last_status
)
```
Токен кладётся в URL вебхука HAE: `/functions/v1/ingest-health?token=...`.
Функция по токену находит user. Дедуп обеспечивают unique-констрейнты.

### 2.2 Staging (зеркало боевых, изолированно)
```sql
ingest_raw (id, user_id, received_at, payload jsonb)        -- сырой JSON как пришёл
metrics_daily_staging (user_id, date, metric, value, source) -- разобранные метрики
sleep_sessions_staging (user_id, date, duration_hours, deep_hours, ...)
```
Боевые таблицы остаются нетронутыми, пока mode='shadow'.

## 3. Поток `ingest-health`
1. Валидируем токен → user, иначе 401.
2. Сохраняем сырой `payload` в `ingest_raw` (всегда — для отладки/реплея).
3. Маппинг HAE JSON → метрики/сон (см. §4).
4. Применяем **серверный дедуп = паритет с воркером** (см. §5).
5. Пишем в `*_staging`.
6. Если mode='live' — промоут в боевые таблицы тем же upsert'ом.
7. Обновляем `last_ingest_at/last_status`.

## 4. Маппинг HAE JSON (уточнить по реальной выгрузке телефона)
HAE шлёт агрегаты по дням. Ориентировочно:
- `step_count` → metric `steps`
- `heart_rate` (avg/min/max) → `heartRate`/`restingHeartRate`
- `heart_rate_variability` → `hrv`
- `sleep_analysis` (фазы) → `sleep_sessions_staging`
- `active_energy` → `active_energy`
- `blood_oxygen_saturation` → `oxygenSaturation`
**До реализации**: снять один реальный экспорт с телефона и зафиксировать точные имена полей/единицы.

## 5. Паритет правил корректности (критично)
Сервер обязан повторить логику воркера, иначе вернутся старые баги:
- шаги/дистанция/калории: **сумма внутри источника, максимум по источникам** (iPhone+Watch не задваивать);
- сон: длительность = **объединение интервалов**, не сумма; интервалы >16ч отбросить;
- SpO₂ хранить как долю (×100 при показе);
- дистанция в км.
Если HAE уже агрегирует по-своему — проверить, не задваивает ли, и при необходимости брать его агрегат как один «источник».

## 6. План тестирования (как убедиться, что не сломали)
1. Включить mode='shadow', настроить HAE на телефоне, дождаться 1-2 выгрузок.
2. **Экран сверки** (Настройки → Авто-синхронизация, debug): рядом за одни даты —
   `metrics_daily` (боевое, текущее) vs `metrics_daily_staging` (новое).
   Зелёным совпадения, красным расхождения.
3. Критерии приёмки: шаги без выбросов >40k, сон <16ч, значения совпадают с
   боевыми в пределах разумного на пересекающихся днях.
4. Только после ОК — переключить на mode='live'.
5. Боевые upsert'ы защищены unique-констрейнтами → даже при ошибке повтор не задваивает; откат = вернуть mode='shadow'.

## 7. Аутентификация и приватность
- Per-user токен, отзываемый (regenerate). Скомпрометирован — перевыпустить.
- Всё под RLS. Сырой `payload` хранить ограниченно (напр. 30 дней) — чистить cron'ом.

## 8. Этапы
- **A1:** `ingest_tokens` + `ingest_raw` + функция, которая просто принимает и сохраняет сырой JSON (mode=shadow). Проверить, что HAE достучался.
- **A2:** маппинг по реальному JSON → `*_staging`.
- **A3:** серверный дедуп = паритет (§5).
- **A4:** экран сверки staging vs боевое (§6).
- **A5:** переключатель shadow→live + промоут в боевые таблицы.
- **A6:** очистка `ingest_raw` cron'ом.
