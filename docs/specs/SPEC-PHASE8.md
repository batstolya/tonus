# Tonus — ТЗ фаза 8: рекомендации, цели и отслеживание (ИИ-коуч)

Продолжение `SPEC.md` … `SPEC-PHASE7.md`. Здесь — система, которая замыкает петлю: данные → инсайт → рекомендация → цель → отслеживание прогресса → обратная связь ИИ. ИИ перестаёт только описывать и начинает вести к результату.

---

## 0. Что нового и общая идея

Петля:
1. **Инсайт** — ИИ/движок находит паттерн («засыпаешь поздно»).
2. **Рекомендация** — предлагает шаг («ложиться раньше»).
3. **Цель** — превращается в измеримую цель от личной базы («сдвинуть засыпание к 00:00 за 2 недели»).
4. **Отслеживание** — прогресс считается автоматически по уже собираемым данным.
5. **Обратная связь** — ИИ подстраивает цель, прогресс идёт в дашборд, в двухнедельный отчёт (фаза 7) и доступен в чате.

## 1. Движок рекомендаций

- Источник — инсайты (фаза 6) и двухнедельный анализ (фазы 4/7): отклонения от базы, корреляции, просадки.
- Рекомендация = конкретный шаг с обоснованием на личных данных («поздние отбои + кофе после 16:00 → попробуй раньше кофе и раньше спать»).
- Пользователь может принять рекомендацию (→ цель), отложить или отклонить. Отклонённые не навязываются повторно.

## 2. Цели

### Принципы
- **От личной базы, а не от абстрактных норм.** База берётся из реальных данных пользователя.
- **Постепенность.** Большой сдвиг разбивается на шаги (например, засыпание раньше по 15 минут в неделю).
- **Измеримость и срок.** У цели есть показатель, целевое значение, направление и период.
- **Фокус.** Одновременно 1–3 активные цели, не больше.

### Типы целей
- **Целевое значение показателя** — среднее время засыпания, длительность сна, пульс покоя, HRV, шаги.
- **Привычка/поведение** — ежедневный приём саплемента (связь с фазой 5), кофе не позже X, медитация.
- **Тренд** — улучшить показатель на X% относительно базы.

### Пример
База: засыпание в среднем 01:00. Цель: к 00:00 за 2 недели, шагами по 15 мин/нед. Каждый день фактическое время засыпания берётся из данных сна, сверяется с текущей промежуточной целью.

## 3. Отслеживание и прогресс

- Прогресс считается **автоматически** из уже собираемых данных (сон, активность, приём саплементов и т.д.).
- Визуализация: прогресс-кольцо/полоса, «X из 14 дней в цели», тренд против целевой линии.
- Авто-оценка статуса: в графике / отстаёт / достигнуто / период закончился.
- Никакого ручного ведения — система сама считает по данным.

## 4. Привязка ИИ (коуч)

- **Предлагает** цели из паттернов.
- **Подстраивает**: справляешься — следующая планка; буксуешь — смягчает или подсказывает причину через корреляции.
- **Прогрессия**: при достижении цели предлагает следующий шаг, при провале — разобраться почему, а не просто «не вышло».
- **В отчёте и чате**: прогресс целей включается в двухнедельный отчёт (фаза 7); в чате (фаза 5) можно обсудить цель и попросить скорректировать.
- Через Telegram-бота (фаза 7): уведомления о прогрессе, принятие/отклонение предложенных целей командами.

## 5. Жизненный цикл цели

`предложена (ИИ) → принята → активна (трекинг) → оценка (в графике / отстаёт) → достигнута / не достигнута → следующий шаг (ИИ предлагает прогрессию или новую цель)`

Точки пересмотра привязаны к двухнедельному циклу отчёта.

## 6. Забота о пользователе (обязательные рамки)

- **Мягкая подача.** Без «ты сорвал серию» и наказывающих формулировок. Акцент на постоянстве, а не идеальности; пропуск — не провал.
- **Безопасные цели.** ИИ не ставит рискованных целей: никакого агрессивного дефицита калорий, экстремальной нагрузки, недосыпа ради «активности». Для питания/веса/нагрузки — только умеренные, здоровые диапазоны.
- **Без навязчивости.** Ограниченное число активных целей; пользователь может в любой момент поставить на паузу или удалить цель.
- **Не давить тревогой.** Цель — помогать, а не превращаться в источник стресса. Формулировки поддерживающие.
- Тон ИИ — коуч-помощник, без диагнозов; при тревожных сигналах — мягко к врачу.

## 7. Модель данных (дополнения)

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `recommendations` | предложения ИИ | user_id, source_insight, text, metric, suggested_target, status (new/accepted/dismissed), created_at |
| `goals` | цели пользователя | user_id, metric, baseline_value, target_value, direction, step_plan, start_date, end_date, status, parent_recommendation_id |
| `goal_progress` | оценки прогресса по дням | user_id, goal_id, date, value, on_target |

Прогресс можно частично считать на лету из существующих таблиц показателей; `goal_progress` — для снимков/истории. Все таблицы под RLS.

## 8. UX / дашборд

- Блок «Цели» на дашборде: активные цели с прогресс-кольцами и коротким статусом.
- Карточки рекомендаций от ИИ с кнопками «Сделать целью / Позже / Скрыть».
- Экран цели: график факт vs целевая линия, текущий шаг, история, кнопки паузы/удаления.
- В двухнедельном отчёте и в чате — сводка по целям.

## 9. Этапы

- **8a:** цели вручную (создание, измеримость от базы, авто-трекинг прогресса, визуализация).
- **8b:** движок рекомендаций (ИИ предлагает цели из инсайтов/анализа) + принятие/отклонение.
- **8c:** адаптивность (прогрессия/смягчение, привязка к причинам через корреляции).
- **8d:** интеграция в двухнедельный отчёт и Telegram-бот; рамки заботы о пользователе.

## 10. Принятые решения

1. Цели — от личной базы и постепенные (шагами), а не от абстрактных норм. **Решено: да.**
2. Прогресс считается автоматически из данных, без ручного ведения. **Решено: да.**
3. 1–3 активные цели, мягкая подача без штрафов за срывы. **Решено: да.**
4. ИИ не ставит рискованных целей (питание/нагрузка — только умеренные). **Решено: да, обязательно.**
