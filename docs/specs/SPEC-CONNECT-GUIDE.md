# Tonus — ТЗ: анимированный гайд подключения устройства (первый запуск)

Сейчас новый пользователь после регистрации видит `DeviceSelectScreen` и экран загрузки
файла, а вся инструкция по авто-синхронизации — один абзац текста, спрятанный в
Настройки → «Авто-синхронизация» → «Настроить». Человек без подсказки не догадается,
что такое Health Auto Export, где его взять и куда вставить вебхук.

Задача — красивый пошаговый гайд с анимациями, который за 3-5 минут доводит нового
пользователя от «пустого аккаунта» до «первые данные пришли» без чтения документации.

---

## 0. Когда показывается

- **Триггер:** пользователь залогинен, `hasData === false` **и** нет успешного приёма
  (`ingest_tokens.last_ingest_at IS NULL`). Тогда вместо голого экрана выбора устройства —
  гайд (выбор устройства становится его первым шагом).
- Повторный вход без данных → гайд продолжается **с того шага, где остановился**
  (прогресс в `localStorage`, ключ `tonus.connectGuideStep`; сервер не трогаем).
- «Пропустить» доступен всегда (в углу, не конкурирует с основным CTA) → попадает на
  текущий экран ручной загрузки. Вернуться можно из Настроек → «Как подключить устройство».
- В демо-режиме (`VITE_DEMO=1`) гайд доступен по кнопке из настроек, но не блокирует
  демо-данные; шаг «жду данные» в демо сразу показывает успех на фикстурах.

## 1. Шаги гайда (ветка Apple Watch / iPhone)

Формат: полноэкранный wizard, один шаг = один экран, прогресс-точки сверху,
навигация «Далее/Назад». Каждый шаг — крупная анимированная иллюстрация + 1-2 короткие
фразы, без простыней текста.

1. **Выбор устройства** — текущие карточки Apple Watch / Xiaomi (переиспользуем
   `DeviceSelectScreen` как шаг, а не отдельный экран). Ветка Xiaomi — §2.
2. **Что произойдёт** — анимация «часы → телефон → облако Tonus → графики»: объясняем
   схему одним предложением («данные будут приходить сами, каждый день»).
3. **Установи Health Auto Export** — иконка приложения, кнопка-ссылка в App Store
   (`https://apps.apple.com/app/id1115567069`). Явно сказать: **у HAE есть бесплатный
   trial** — хватит, чтобы всё проверить перед покупкой; автоматизации — премиум-функция.
4. **Создай автоматизацию** — анимированный мини-скринкаст шагов внутри HAE
   (стилизованные экраны, не скриншоты — их не надо переснимать при обновлениях HAE):
   Automations → «+» → тип **REST API**, метод POST, формат JSON.
5. **Вставь адрес Tonus** — показываем персональный вебхук-URL (через существующий
   `ensureToken`/`webhookUrl` из `lib/autosync.ts`) с большой кнопкой «Скопировать»
   и анимацией подтверждения копирования.
6. **Выбери данные и расписание** — рекомендация: все метрики здоровья + сон,
   интервал — каждые 1-3 часа или «при открытии приложения»; напомнить нажать
   «Enable» у автоматизации.
7. **Проверка связи** — просим в HAE нажать «Manual Export» → Tonus **ждёт вживую**:
   поллинг `ingest_tokens.last_ingest_at` раз в 5 сек (до 2 минут). Состояния:
   - ожидание — пульсирующая анимация «слушаем эфир»;
   - успех — конфетти/чекмарк, «Данные пришли! Первые графики появятся после
     следующей синхронизации» → кнопка «В приложение»;
   - таймаут — не ошибка, а мягкая подсказка: чеклист типичных проблем (URL вставлен
     целиком? метод POST? формат JSON?) + кнопка «Проверить ещё раз».

Данные при этом идут в staging (mode=shadow) — существующая механика сверки и
переключения в live не меняется; для нового пользователя без исторических данных
допустимо включать live сразу после первого успешного приёма (решение зафиксировать
при реализации B-этапов, дефолт — shadow).

## 2. Ветка Xiaomi / Mi Band

Шаги 1-2 общие, дальше ветвление по платформе телефона (вопрос «какой у тебя телефон?»):

- **iPhone:** шаг «включи в Mi Fitness синк с Apple Health» (анимированная подсказка
  Профиль → Настройки → Apple Health), дальше — шаги 3-7 ветки Apple как есть.
- **Android:** шаги по `SPEC-BANDS-AUTOSYNC.md` §1.2 (Mi Fitness → Health Connect →
  приложение-экспортёр → вебхук). Пока B2-B3 не сделаны — показываем путь
  «Разовый импорт CSV» (текущая инструкция account.xiaomi.com) с пометкой
  «авто-синхронизация для Android скоро».
- **CSV-импорт:** остаётся третьей опцией без wizard-а — сразу текущий `UploadScreen`.

## 3. Анимации

- **Motion** (уже в проекте): `LazyMotion` + `domMax` strict, только `m.*` — по
  конвенции проекта. Никакого нового анимационного стека.
- Иллюстрации шагов — инлайн-SVG со стилизованными устройствами (в духе
  `HowItWorks` на лендинге). Помнить про `useId()` для градиентов — дубликаты id
  уже ломали лендинг.
- Переходы шагов — spring slide + fade; иллюстрации — staggered появление элементов;
  «ожидание данных» — бесконечный pulse; успех — одноразовый burst.
- Уважать `prefers-reduced-motion`: анимации заменяются на статичные состояния.

## 4. Компоненты

```
src/components/onboarding/
  ConnectGuide.tsx          — wizard-контейнер: шаги, прогресс, localStorage
  guide/StepDevice.tsx      — шаг 1 (обёртка DeviceSelectScreen)
  guide/StepExplain.tsx     — шаг 2 (схема «часы → Tonus»)
  guide/StepInstallHAE.tsx  — шаг 3
  guide/StepAutomation.tsx  — шаг 4 (мини-скринкаст)
  guide/StepWebhook.tsx     — шаг 5 (токен + копирование)
  guide/StepSchedule.tsx    — шаг 6
  guide/StepVerify.tsx      — шаг 7 (поллинг last_ingest_at)
  guide/illustrations/…     — SVG-сцены
```

- `App.tsx`: ветка `!hasData` рендерит `ConnectGuide` вместо голого
  `DeviceSelectScreen` (`DeviceSelectScreen` не удаляется — живёт внутри шага 1).
- Настройки: пункт «Как подключить устройство» открывает гайд поверх приложения
  (для тех, кто пропустил или меняет устройство).
- Поллинг шага 7 — в `lib/autosync.ts` (`waitForFirstIngest(userId, {timeoutMs})`),
  логика отделена от UI и тестируется vitest-ом напрямую (окружение node,
  рендер компонентов недоступен — тесты компонентов по паттерну «экспорт + переводы»,
  см. `TelegramDemo.test.ts`).

## 5. Переводы

Все строки — через `t()` с покрытием uk/en (skill `adding-translations`).
Тексты шагов короткие и императивные («Установи…», «Вставь…», «Нажми…»).

## 6. Тесты и приёмка

- Vitest: `waitForFirstIngest` (успех/таймаут, фейковые таймеры); экспорт-тесты
  компонентов шагов + покрытие переводов.
- E2E (гард витрины): в демо-режиме гайд открывается из настроек и листается до
  последнего шага.
- Приёмка вручную: новый аккаунт на телефоне → пройти гайд → Manual Export в HAE →
  увидеть конфетти. Засечь время: цель ≤ 5 минут без подсказок со стороны.

## 7. Этапы

- **G1:** каркас wizard (ConnectGuide, прогресс, localStorage, «Пропустить», роутинг
  в App.tsx + пункт в Настройках) с текстовыми плейсхолдерами шагов.
- **G2:** ветка Apple: шаги 3-6 с контентом, шаг 5 на существующем токен-механизме.
- **G3:** шаг 7 «Проверка связи» + `waitForFirstIngest`.
- **G4:** анимации и SVG-иллюстрации (Motion, reduced-motion).
- **G5:** ветка Xiaomi (iPhone-путь + заглушка Android до готовности SPEC-BANDS B3).
- **G6:** переводы, e2e-гард, полировка.
