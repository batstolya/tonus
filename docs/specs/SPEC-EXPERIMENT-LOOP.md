# Tonus — ТЗ: Петля экспериментов (запуск из бота + автовердикт)

Замыкает цикл экспериментов. Сейчас: идеи генерит `suggest-experiments`
(только в приложение), запуск — вручную на экране «Эксперименты», результат
виден, только если зайти в приложение после `end_date`. Эксперимент, о котором
забыл, — потерянный эксперимент.

Переиспользует готовое: движок результатов `src/lib/experiments.ts`
(`computeResult`, `effectLabel`), генерацию идей `suggest-experiments`,
планировщик `send-reminders` (pg_cron, 5 мин), доставку и callback-роутинг
`telegram-bot`, леджер `coach_events`.

---

## 0. Цель

Пользователь запускает эксперимент в два тапа из Telegram и **гарантированно**
получает вердикт с размером эффекта, когда эксперимент закончился, — без
захода в приложение.

## 1. Принципы

- **Минимум шума** — никаких ежедневных чек-инов; ровно два касания:
  предложение при запуске и вердикт в конце (решение пользователя, 2026-07-12).
- **Одна правда о результате** — вердикт считает тот же алгоритм, что и экран
  «Эксперименты»: серверная копия обязана быть зеркальной и покрытой
  parity-тестом (политика как у `scores.ts`).
- **Честная статистика** — вердикт наследует пороги движка (мин. 5 парных
  дней, эффект по Коэну); «мало данных» — это тоже честный вердикт.

## 2. Компоненты

### 2.1 Серверный движок результатов — `_shared/experiments.ts`

Зеркальная копия чистой логики из `src/lib/experiments.ts`:
`computeBaselineStart`, `computeResult`, `effectLabel`, типы
`ExperimentRow`/`ExperimentResult`. Без Deno-специфичных импортов — файл
тестируется vitest напрямую.

**Обязательный parity-тест** (vitest): один набор фикстур прогоняется через
обе копии, результаты сравниваются полем в поле. Тест падает — копии разъехались.

### 2.2 Автовердикт — новый блок в `send-reminders` (§12)

Раз в день в 09:10 по таймзоне пользователя (`report_settings.timezone`,
fallback `Europe/Kyiv`; паттерн `timeDue`, как утренняя сводка):

1. `experiments` со `status = 'active'` и `end_date < today` (локальная дата
   пользователя, `localDate` из `_shared/time.ts`).
2. Загрузить `daily_metrics` за окно `baseline_start … end_date`, посчитать
   `computeResult` серверно.
3. Одним `update … where id = … and status = 'active'` перевести в
   `completed` + записать `result`. Условие по `status` — защита от двойной
   отправки при параллельных ранах (обновилось 0 строк → вердикт уже отправлен
   другим раном, выходим).
4. Отправить в Telegram вердикт (только после успешного шага 3).

Формат вердикта:

```
🧪 Эксперимент завершён: «Кофе только до обеда»

Метрика: сон
До: 6.8 ч → Во время: 7.4 ч (+0.6 ч)
Эффект: заметный (d = 0.62), 12 парных дней

Подробности и график — в приложении → Эксперименты.
```

При `n < 5` парных дней: «данных мало, чтобы судить об эффекте — вердикт
неубедительный» (без вымышленных выводов). Нет активной телеграм-связки
(`telegram_links`) → только перевод в `completed`, без сообщения.

### 2.3 Запуск из бота

- Пункт в `/menu` бота: «🧪 Предложи эксперимент».
- `telegram-bot` дёргает `suggest-experiments`
  function-to-function (service key + `x-user-id`, паттерн вызова
  `biweekly-report` из `send-reminders`). В `suggest-experiments` этот путь
  нужно добавить: сейчас функция принимает только пользовательский JWT.
  Бюджет ИИ учитывается как обычно (`checkBudget` уже есть в боте).
- Топ-2 идеи приходят двумя сообщениями. Каждая идея сохраняется в
  `coach_events` (`type = 'exp_suggestion'`, `payload` = идея целиком,
  `status = 'open'`), под сообщением кнопка
  `▶️ Запустить (14 дней)` с `callback_data = expsug:<coach_event_id>`
  (в 64 байта callback_data влезает только id — сама идея живёт в payload).
- Callback `expsug:` → прочитать payload, `insert` в `experiments`
  (`hypothesis`, `change_rule`, `target_metric` из идеи; `start_date` = завтра,
  `end_date` = +14 дней, `baseline_days` = 14), `coach_events.status = 'done'`,
  ответить: «Запустил. Стартуем завтра, вердикт пришлю ДД.ММ».
- Повторный тап по той же кнопке (`status != 'open'`) → «уже запущен», без
  дубля.

### 2.4 Приложение

Изменений экрана не требуется: `completed`-эксперимент с готовым `result`
экран уже отображает. Единственное изменение — экран должен предпочитать
сохранённый `result` пересчёту, если он есть (сервер уже посчитал финально).

## 3. Данные

Новых таблиц нет. Используются `experiments` (без изменений схемы),
`coach_events` (новый `type = 'exp_suggestion'`), `ai_usage`
(`source = 'suggest-experiments'` — уже пишется).

## 4. Критерии приёмки

1. Parity-тест `src/lib/experiments.ts` ↔ `_shared/experiments.ts` зелёный.
2. Активный эксперимент с `end_date` вчера: после утреннего тика —
   `status = 'completed'`, `result` заполнен, в Telegram пришёл вердикт;
   повторный тик не шлёт второй раз.
3. «🧪 Предложи эксперимент» в `/menu` → две идеи с кнопками; тап — эксперимент
   в БД и подтверждение; повторный тап — «уже запущен».
4. Эксперимент с < 5 парных дней завершается с честным «мало данных».
5. Лимит ИИ-бюджета исчерпан → бот отвечает штатным сообщением бюджета,
   идей не генерит.

## 5. Вне скоупа

Ежедневные чек-ины соблюдения, параллельные эксперименты с взаимным контролем,
A/B-дизайны с рандомизацией, запуск произвольного эксперимента текстом из бота
(только из предложенных идей).
