# Tonus — ТЗ: выбор устройства при первой загрузке и адаптивный интерфейс

Дополнение к `SPEC-DEVICES.md`. Описывает онбординг с выбором источника данных и то, как от выбора зависит загрузка и отображение показателей.

---

## 0. Цель

При первой загрузке пользователь выбирает своё устройство (Apple Watch или Xiaomi-браслет). От этого зависит: подсказки по выгрузке в нужном формате, ожидаемый формат файла и **какие показатели показывать** — выводим всё, что реально пришло с датчиков этого устройства, без пустых разделов.

## 1. Шаг выбора устройства

- При первой загрузке — вопрос: «Какое у вас устройство?» с вариантами **Apple Watch** и **Xiaomi (Mi Band)**. На будущее список расширяемый.
- Выбор сохраняется в профиле; можно сменить/добавить источник позже в настройках.
- В аккаунте может быть несколько источников (например, у разных пользователей разные устройства) — выбор привязан к загрузке, не глобально жёстко.

## 2. Флоу загрузки под устройство

- **Apple Watch:** инструкция по экспорту Apple Health (`export.xml`/zip) → импорт `AppleHealthImporter`.
- **Xiaomi:** инструкция по прямому экспорту Xiaomi (account.xiaomi.com → Privacy → Manage → zip с CSV) → импорт `XiaomiCsvImporter`. Для Xiaomi это основной путь — даёт пульс и фазы сна (см. `SPEC-DEVICES`).
- Каждый вариант показывает свои шаги-онбординг и принимает свой формат файла; неверный формат — понятная ошибка с подсказкой.

## 3. Адаптивное отображение показателей (важно)

- Набор датчиков у Apple Watch и Xiaomi разный, и различается даже между моделями. Поэтому **не хардкодить** список показателей по устройству.
- После разбора файла приложение определяет **фактически доступные показатели из самих данных** и строит интерфейс по ним.
- Показываем всё, что реально пришло с датчиков; разделы/карточки без данных — скрываем (или помечаем «нет данных с этого устройства»), чтобы не было пустых экранов.
- Выбор устройства используется как подсказка (чего ожидать и как назвать источник), но финальный источник истины — сами данные.

## 4. Связь с остальной системой

- Источник записи (`source`) и тип источника (`source_type`) сохраняются (см. `SPEC-DEVICES`).
- Дашборд, статистика, сон, стресс, ИИ, цели работают поверх общего формата — независимо от устройства, по фактически доступным показателям.
- Дедупликация между источниками — как в `SPEC-DEVICES`.

## 5. Этапы

- **O1:** экран выбора устройства при первой загрузке + сохранение в профиль.
- **O2:** ветвление флоу загрузки и инструкций под Apple Watch / Xiaomi.
- **O3:** определение доступных показателей из разобранных данных + адаптивное отображение (скрывать пустое).
- **O4:** смена/добавление источника в настройках.

## 6. Принятые решения

1. При первой загрузке — выбор устройства (Apple Watch / Xiaomi), список расширяемый. **Решено: да.**
2. Флоу загрузки и инструкции зависят от выбранного устройства. **Решено: да.**
3. Набор показателей определяется из самих данных, а не хардкодится по устройству; пустые разделы скрываются. **Решено: да.**
4. Выбор устройства — подсказка; источник истины по доступным показателям — фактические данные. **Решено: да.**
