# Tonus — ТЗ: Анимация героя «Apple Watch → сайт» (с переключателем)

## 0. Цель

Заменить в герое лендинга текущее `TelegramDemo` на «прикольную» анимацию,
которая за пару секунд показывает суть Tonus: данные с Apple Watch **сливаются с
сайтом** и дашборд **оживает**. Две сцены, между которыми пользователь
переключается.

## 1. Контекст

- Сейчас в герое (`HeroBlock`,
  [../../../src/components/landing/blocks/HeroBlock.tsx](../../../src/components/landing/blocks/HeroBlock.tsx))
  рендерится `TelegramDemo`.
- `TelegramDemo`
  ([../../../src/components/auth/TelegramDemo.tsx](../../../src/components/auth/TelegramDemo.tsx))
  **также используется в `AuthScreen`**
  ([../../../src/components/auth/AuthScreen.tsx](../../../src/components/auth/AuthScreen.tsx)) —
  там остаётся без изменений.
- Этот блок развивает существующий лендинг
  ([2026-06-26-landing-page-design.md](2026-06-26-landing-page-design.md)):
  раскладка героя и техника анимаций (чистый CSS + `useInView`) сохраняются.
- Недавний фикс (коммит `c493250`) убрал лаг и самопрокрутку из `TelegramDemo`.
  Уроки оттуда заложены в §6 и §9: только `transform`/`opacity`, без вечных
  таймеров со `scrollTo`, пауза анимации вне вьюпорта.

## 2. Что видит пользователь

Раскладка героя прежняя (грид: слева заголовок + подзаголовок + CTA, справа
визуал; см. `.landing-hero-grid` в
[../../../src/components/landing/Landing.css](../../../src/components/landing/Landing.css)).
Справа — анимационный блок с **двумя сценами** и переключателем (2 точки +
короткие подписи). По умолчанию активна сцена «Превращение».

## 3. Сцены

### 3.1. Превращение (`morph`) — по умолчанию

1. Циферблат часов: три кольца активности (red/green/cyan).
2. Циферблат «разворачивается» в дашборд сайта.
3. В дашборде **всплывают графики**: линия рисуется (`stroke-dashoffset`), бары
   растут (`scaleY`), карточка пульса `❤️ 58 bpm` — число считается 0→58 через
   переиспользованный `Counter`.
4. Короткая пауза → цикл повторяется.

### 3.2. Поток + Telegram (`flow`)

1. Слева — часы (кольца активности).
2. Точки-данные летят по «проводу» вправо, в сайт (центр).
3. В сайте всплывают те же графики (линия / бары / `❤️ 58 bpm`).
4. Справа — плитка Telegram; **двусторонняя связь** сайт ⇄ Telegram (точки летят
   в обе стороны: туда — сообщения, обратно — инсайты). Над плиткой всплывает
   пузырь «💡 инсайт».
5. Цикл повторяется.

## 4. Переключатель и поведение

- Две точки-дотса (паттерн как в `TelegramDemo`) + короткие локализованные
  подписи «Превращение» / «Поток + Telegram»; у кнопок `aria-label`.
- Дефолт: `morph`.
- **Авто-смена** режимов раз в ~9 c; ручной клик по дотсу перебивает и сбрасывает
  таймер.
- Авто-смена и анимации **на паузе**, когда герой не во вьюпорте (`useInView`) и
  при `hover`/`focus` на блоке (чтобы пользователь успел рассмотреть).
- Точки активной сцены подсвечены.

## 5. Архитектура и файлы

- Новый `src/components/landing/HeroShowcase.tsx` — оркестратор: стейт `mode`
  (`'morph' | 'flow'`), таймер автосмены (с паузой), переключатель, рендер
  активной сцены; `role="img"` + `aria-label`.
- Сцены — подкомпоненты `MorphScene` и `FlowScene` (в том же файле).
- `src/components/landing/HeroShowcase.css` — стили + `@keyframes`, всё под

  тему, как сделано в `TelegramDemo.css`).
- Переиспользуем `Counter`

- Правка: `HeroBlock.tsx` рендерит `<HeroShowcase/>` вместо `<TelegramDemo/>`.
- `TelegramDemo` и `AuthScreen` — без изменений.

- Новые строки — в

## 6. Анимации (технически)

- Чистый CSS `@keyframes`; запуск/пауза через `useInView` (IntersectionObserver,
  `once: false`) — анимации идут **только когда блок виден**.
- Анимируем только `transform` / `opacity`. Линия графика — `stroke-dashoffset`
  (уже применяется на лендинге, дёшево для маленького `path`).
- «Превращение» — через `transform: scale()` + кроссфейд (`opacity`) между
  циферблатом и дашбордом; `width` / `height` **не** анимируем.
- **Не** анимируем `box-shadow` / `filter` в циклах: свечение Telegram —
  `opacity` отдельного слоя-подложки.
- `contain: layout paint` на корне компонента.
- Никаких `setInterval` + `element.scrollTo` (прямая причина прошлого бага).

## 7. Reduced-motion

При `prefers-reduced-motion: reduce` — статичный финальный кадр дефолтной сцены
(дашборд с графиками + часы + Telegram), без циклов и без автосмены.

## 8. i18n

Подписи переключателя, текст пузыря инсайта, подпись `bpm` и прочие видимые
тексты-демо — через `useT` / `t()`, ru по умолчанию, uk/en. Новые строки в
`translations.ts`.

## 9. Производительность

- Бюджет: 60fps при скролле; анимация не создаёт long-tasks; цикл на паузе вне
  вьюпорта.
- Проверка (Playwright, как при фиксе лага): (а) нет самопрокрутки и скролл-джанка;
  (б) при уходе героя за экран анимация встаёт на паузу; (в) reduced-motion даёт
  статичный кадр.

## 10. Тестирование

- Окружение **node** (без рендера DOM, см. CLAUDE.md): юнит на экспорт компонента
  + покрытие переводов (паттерн
  [../../../src/components/auth/TelegramDemo.test.ts](../../../src/components/auth/TelegramDemo.test.ts)).
- Чистая логика `nextMode` — юнитом напрямую.
- Существующие smoke-тесты лендинга остаются зелёными (рендер при `!user`,
  «Попробовать» открывает `AuthScreen`).
- Визуал и перф — вручную через Playwright (см. §9).

## 11. Вне рамок (YAGNI)

- Реальные фото устройств / скриншоты — только стилизованные CSS-мокапы.
- Реальные данные или API — тексты и числа захардкожены в демо.
- 3D / WebGL / canvas, звук.
- Анимационные библиотеки (framer-motion / Lottie).
- Отдельная анимация для `AuthScreen` (остаётся `TelegramDemo`).

## 12. Зафиксированные решения

- Дефолтная сцена — `morph` (Превращение).
- Авто-смена режимов + ручной клик.
- `AuthScreen` остаётся на `TelegramDemo`.
- Имя компонента — `HeroShowcase`.
