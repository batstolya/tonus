# Магнитные бури и давление в блоке «Связи» (Insights)

**Дата:** 2026-07-11 · **Статус:** approved (юзер: «делай, даю добро после спеки и сливай»)

## Контекст — что уже есть

Факторы среды считаются в ДВУХ независимых движках:

| Движок | Файл | Давление | Перепад давл. | Магн. бури (Kp) |
|---|---|:--:|:--:|:--:|
| «Дослідження» (Пирсон, топ-25) | `src/lib/research.ts` | ✅ | — | ✅ (env_kp) |
| «Связи» (лаг-корреляции, топ-5) | `src/lib/correlations.ts` | ✅ | ✅ | ❌ |

То есть **давление уже полностью в анализе** (в «Связях» даже с перепадом
день-к-дню — `pressureDelta`). А **магнитные бури есть только в «Дослідження»**:
в `correlations.ts` они не заведены, и `CorrelationsBlock` даже не грузит
`kp_index` из `environment_daily`.

## Задача

Добавить магнитные бури как фактор в блок «Связи» (Insights), параллельно
давлению. Тогда бури — полноценный фактор в обоих движках.

## Изменения (`src/lib/correlations.ts`, `CorrelationsBlock.tsx`)

1. `EnvDay`: добавить `kp_index: number | null`.
2. `CorrFactor`: добавить `'magneticStorm'`; `factorValue` возвращает
   `envByDay.get(d.date)?.kp_index ?? null` (Kp за день = максимум, уже так
   пишется в `fetch-environment`); добавить в список `factors`.
3. `CorrelationsBlock`: в select добавить `kp_index`; лейбл
   `magneticStorm: { emoji: '🧲', label: 'Магнитные бури' }`.
4. Демо-фикстура уже отдаёт `kp_index` (менять не нужно).
5. Переводы лейбла (uk/en), тесты в `correlations.test.ts` на новый фактор.

## Вне скоупа (осознанно)

- **Per-factor on/off тумблеры в настройках.** Факторы среды автоматически
  участвуют в анализе, когда есть данные; отдельные переключатели добавят
  UI-сложность без пользы (YAGNI). Карточка «Дані середовища» уже говорит,
  что бури и давление тянутся для корреляций.
- Давление в «Связях» уже есть — не трогаем.

## Деплой

Только фронт → обычный CI. БД/функции не трогаем (`kp_index` уже в проде,
авто-синк среды заполняет его ежедневно).
