# Дизайн: геймифицированный home — стрик, календарь активности, empty states

**Дата:** 2026-07-09
**Статус:** утверждён (brainstorming)
**Источник идеи:** инвестигейт дашборда mate.academy/home — перенос «высоких» паттернов
(стрик-система, календарь активности, first-class пустые/locked-состояния).

## Цель

Поднять уже существующие, но «зарытые» механики Tonus (стрики привычек в Insights,
хитмапы, баннер пробелов) в первоклассный геймифицированный блок на главном экране —
в духе дашборда mate.academy. Заменить демотивирующий staleness-баннер на home
дружелюбным стрик-виджетом.

## Не-цели (YAGNI)

- Никакой персистентной серверной механики стрика (таблиц, edge-функций, RLS).
- Никакого лидерборда/сравнения с другими пользователями (здоровье приватно).
- Никаких ручных «подарков» заморозок и истории списаний.
- Никаких новых цветовых токенов или тёмной темы.

## Ключевые решения

1. **Объём:** все три паттерна в одной связной спеке «геймифицированный home».
2. **Стрик = «день с данными» (синк):** активный день — день с любой ненулевой
   core-метрикой. Низкое трение, естественно заменяет staleness-баннер.
3. **Freeze-валюта (как у mate):** заморозки копятся от длины стрика, авто-тратятся
   на пропуски.
4. **Архитектура A — чистая деривация на клиенте:** стрик и заморозки — чистая
   функция от уже загруженного `daily: DailyMetrics[]`. Ноль изменений в БД, ноль
   edge-функций, детерминированно, покрывается юнит-тестами.

## Архитектура

### Расположение
Новый блок в шапке `src/components/dashboard/Dashboard.tsx`, между greeting и сеткой
метрик:

- **StreakWidget** — «Денний / Заморожено ❄️ / Тижневий» + огонёк 🔥, крупные числа
  (переиспользуем `src/components/common/CountUp`).
- **ActivityCalendar** — месяц кружков-дней: активный залит, сегодня подсвечен,
  замороженный — со снежинкой.

Оба питаются одним таймлайном `daily` (Dashboard уже получает его пропсом).
Существующий staleness-баннер на home уступает место стрику. В
`Settings/AutoSyncSettings` баннер остаётся как есть (техническо-диагностический).

### Стрик-движок — `src/lib/streak.ts` (чистая функция)

Вход — `DailyMetrics[]`, выход — `StreakState`. Ноль БД.

```ts
interface StreakState {
  current: number          // дней подряд
  freezesAvailable: number // 0..MAX_FREEZES
  freezesSpent: number     // потрачено в текущем окне
  weekly: number           // недель подряд с ≥ WEEKLY_MIN_DAYS активными днями
  todayPending: boolean    // сегодня ещё нет данных, но стрик жив
  frozenDates: string[]    // дни, закрытые заморозкой (для календаря)
}
```

**Активный день** = день, у которого хотя бы одна core-метрика не null:
`steps | sleepHours | restingHeartRate | hrv`.

**Именованные константы** (вверху файла):
- `FREEZE_EARN_EVERY = 7` — 1 заморозка за каждые 7 дней стрика.
- `MAX_FREEZES = 3` — потолок.
- `WEEKLY_MIN_DAYS = 5` — минимум активных дней в неделе для недельного стрика.

**Алгоритм** (идём назад от сегодня по локальным датам):
1. Строим множество активных дат из `daily`.
2. Сегодня без данных ⇒ `todayPending = true`; стрик не ломается (синк ещё может
   прийти) — отсчёт начинаем с последнего активного дня.
3. Идём назад по дням:
   - день активен ⇒ `current++`;
   - день пропущен ⇒ если доступна заморозка — тратим (`freezesSpent++`, дату в
     `frozenDates`) и продолжаем; иначе — обрыв.
   - доступно заморозок в каждый момент = `min(MAX_FREEZES, floor(current / FREEZE_EARN_EVERY)) − freezesSpent`.
4. `weekly` — число подряд идущих календарных недель (от текущей назад), где
   активных дней `≥ WEEKLY_MIN_DAYS`.

Итоговые `freezesAvailable = min(MAX_FREEZES, floor(current / FREEZE_EARN_EVERY)) − freezesSpent`.

**Граничные случаи:** пустой ввод ⇒ всё в 0, `todayPending=false`; единственный
активный день сегодня ⇒ `current=1`; длинная дыра без заморозок ⇒ обрыв на дыре.

### Календарь активности — `src/components/dashboard/ActivityCalendar.tsx`

Текущий месяц, статус каждого дня из `daily` + `frozenDates`. Чистый CSS-grid,
**без recharts** (по заметке: recharts v3 + React 19 капризен, и здесь он не нужен).
Клик по дню — тултип: «синк был / пропуск / заморожено». Переиспользует
подход `buildHeatmap` из `src/utils/insightsExtra.ts` (тот же таймлайн).

### Пустые / locked-состояния — `src/components/ui/EmptyState.tsx`

Один переиспользуемый презентационный компонент: иконка/эмодзи + заголовок +
мотивирующий текст + опциональный CTA. Применения:
- Нет истории вовсе ⇒ «Подключи Apple Health, чтобы начать стрик» + CTA на AutoSync.
- Стрик = 0 ⇒ карточка-приглашение вместо пустого виджета.
- Пробелы в данных ⇒ `DataGaps` остаётся, но дружелюбный вариант рендерится через
  тот же `EmptyState`.

## Визуал и анимации (mate-inspired)

- Каскад появления виджетов — существующий `cardsGridV` (Motion) в Dashboard.
- Огонёк 🔥 при инкременте стрика — лёгкий scale-pulse на Motion.
- Заливка дней календаря — stagger-появление.
- Палитра — существующие токены (`--red` / `--green` / акценты), новые цвета не
  вводим. Только светлая тема проекта.

## i18n

Все строки — через `useT()`, ключи в `src/lib/translations.ts` (uk/en). Покрытие
переводов проверяется тест-паттерном проекта.

## Тестирование

- `src/lib/streak.test.ts` — юнит-тесты vitest (окружение node): границы стрика,
  накопление/трата заморозок, `todayPending`, недельный стрик, пустой ввод, длинная
  дыра.
- Компоненты (`StreakWidget`, `ActivityCalendar`, `EmptyState`) — тест экспорта +
  покрытие переводов (паттерн `src/components/auth/TelegramDemo.test.ts`); node-окружение
  не рендерит React.
- Пороги/формулы стрика живут только в `src/lib/streak.ts` — без дублирования на
  сервер (в отличие от scores), т.к. механика полностью клиентская.
