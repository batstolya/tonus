# Умные подсказки экспериментов (Unit A) — дизайн

**Дата:** 2026-06-21
**Проблема:** `suggest-experiments` (режим generate) кормит ИИ только метриками-исходами (HRV/пульс/сон/шаги) и трендами — без поведения. Поэтому советы generic: «спи больше → улучшит HRV». Пользователь хочет эксперименты про причинность поведения (кофе→сон, время отбоя→HRV).

**Объём:** только серверный фикс промпта в `supabase/functions/suggest-experiments/index.ts`. Никаких новых таблиц/метрик/UI.

## Что меняем

В режиме `generate`, помимо `daily_metrics`, тянем за 30 дней:
- `sleep_sessions` — `bedtime`, `wake_time`, `deep_hours`, `rem_hours` (тайминг и качество сна; раньше функция читала `daily_metrics.sleep_deep`, которого там НЕТ → было пусто).
- `intake_events` — `ts, type` → поведение: кофе (всего + после 16:00), приёмы пищи (всего + поздние после 21:00), алкоголь (дни), тренировки (дни).
- `environment_daily` — `temp_c, daylight_minutes, air_quality, pollen` → контекст среды (жара/пыльца) для rationale.
- `daily_note_settings.timezone` → локальный час событий (для «после 16:00» и среднего времени отбоя). Fallback `Europe/Kyiv`.

Время отбоя/пробуждения усредняем с круговым сдвигом (часы отбоя < 12 трактуем как +24, чтобы 23:00 и 01:00 усреднялись в полночь, а не в полдень).

Дайджест получает разделы **ПОВЕДЕНИЕ (управляемые рычаги)** и **СРЕДА (контекст, не цель)**.

## Промпт (переписан)

Жёсткие правила:
- Каждый эксперимент меняет **конкретную управляемую привычку** из раздела ПОВЕДЕНИЕ (тайминг кофе, поздняя еда, время отбоя/подъёма, алкоголь, активность). Запрет на абстрактное «делай больше метрики Y».
- `change_rule` — точное действие с цифрой/временем («последняя чашка кофе до 14:00», «отбой до 23:30»).
- `target_metric` — измеримый исход из белого списка, на который привычка реально влияет (кофе/еда/отбой → глубокий сон, HRV, длительность; активность → пульс покоя).
- Среда (жара, пыльца) — **не цель** эксперимента (её нельзя менять), только в rationale. (Связи среда→исход покрывает движок корреляций research.ts, куда среду уже завели.)
- `rationale` — ссылка на конкретные цифры поведения/исходов.

`target_metric` остаётся в текущем белом списке (`ALLOWED`) — новых исходов в этом юните не добавляем.

## Не в объёме (→ Unit B)

«Засыпание» (sleepBedtime→минуты, круговая шкала) и «самочувствие 1–5» как **измеримые target_metric** — это новый пайплайн (типы, загрузчик `DailyMetrics`, `computeResult`, логирование в боте/дашборде). Обе — «новые исходы», делаем отдельным юнитом.

## Проверка

- Деплой `suggest-experiments` (verify_jwt остаётся true — вызывается из UI с user-JWT).
- Пользователь жмёт «Подобрать (ИИ)» → подсказки ссылаются на реальные привычки (кофе после 16:00, поздняя еда, время отбоя) и таргетят релевантные исходы, а не «делай больше».
- Деградация: если поведения/среды мало — промпт явно велит предлагать эксперименты по таймингу сна/активности.
