# Tonus — ТЗ: Публичный лендинг (страница-витрина)

## 0. Цель

Публичная страница-витрина перед экраном входа. Объясняет незалогиненному
посетителю, что такое Tonus и зачем он нужен, показывает возможности через
анимации и ведёт к регистрации/входу кнопкой «Попробовать».

Сейчас незалогиненный пользователь попадает сразу в `AuthScreen`
([src/App.tsx](../../../src/App.tsx) строка `if (!user) return <AuthScreen />`).
Задача — показать ему сначала лендинг, а вход оставить в одном клике.

## 1. Аудитория и позиционирование

- **Аудитория:** новые посетители (публичный продукт), не знакомые с Tonus.
- **Тон:** объясняем ценность с нуля, не предполагаем, что человек уже всё знает.
- **Заголовок (черновик):** «Всё о твоём здоровье — в одном месте. И AI, который
  находит, что на тебя реально влияет.»
- Мультипользовательность уже поддержана технически (данные разделены по
  `user_id`), новые регистрации ничего не ломают.

## 2. Структура страницы (сверху вниз)

0. Топбар лендинга: лого «Tonus», переключатель языка (ru/uk/en), «Войти» (ghost) + «Попробовать» (primary)
1. **Hero** — позиционирование + CTA
2. **Дашборд + метрики Apple Watch**
3. **AI-инсайты** (главный дифференциатор)
4. **AI-общение** — «в приложении» ↔ «в Telegram» (объединённый блок с переключением)
5. **Эксперименты (N-of-1)**
6. **Сетка «и это ещё не всё»**
7. **Финальный CTA**

## 3. Блоки — содержание и анимация

Каждый блок запускает анимацию при попадании во вьюпорт (см. §5).

**1. Hero.** Заголовок + подзаголовок + кнопки «Попробовать» (primary) и «Войти»
(ghost). Фон — лёгкая анимация: пульсовая линия бежит по экрану (SVG
`stroke-dashoffset`) + редкие плавающие точки. Без тяжёлой графики.

**2. Дашборд + метрики Apple Watch.** Мокап дашборда. Линейные графики
«рисуются» (`stroke-dashoffset`), бар-чарты вырастают (`scaleY`), числа бегут
0→значение (переиспользуем компонент `Counter` из TelegramDemo). Метрики:
пульс покоя, сон, активность, мини стресс-карта (хитмап-сетка).

**3. AI-инсайты.** Поле «точек данных» → между ними протягиваются линии связи →
выезжают 2–3 карточки-инсайта с примерами («☕ кофе после 15:00 → сон −1.5 ч»,
«🍽️ поздняя еда → HRV −15%»). Подпись: «AI находит закономерности, которые ты
сам не заметишь».

**4. AI-общение (объединённый блок с переключением).** Таб-переключатель:
- «В приложении» — анимированный чат-коуч: вопрос пользователя → «печатает…» → ответ по его данным.
- «В Telegram» — существующий компонент `TelegramDemo` целиком (переиспользуем как есть).

По умолчанию активен первый таб; клик переключает. Авто-переключения нет —
управление вручную.

**5. Эксперименты (N-of-1).** Таймлайн: «Гипотеза: меньше кофе → лучше сон» →
период A / период B на шкале → карточка результата с дельтой («сон +12%», через
`Counter`). Позиционирование: «проверяй, что реально работает именно на тебе».

**6. Сетка «и это ещё не всё».** 6 мини-карточек (иконка + название + строка):
Препараты/лечение · Анализы (лаборатория) · Питание · Цели · Экспорт данных ·
ru/uk/en. Появление со stagger при скролле.

**7. Финальный CTA.** Крупный заголовок-повтор позиционирования + большая кнопка
«Попробовать» → регистрация.

## 4. Интеграция и роутинг

- Новый компонент `LandingScreen` (+ его подкомпоненты блоков).
- Состояние `showAuth` — `useState(false)` в `App.tsx`, действует только в ветке `!user`.
- Логика ветки `!user`:
  - если URL содержит `?reset=1` **или** `passwordRecovery` — показываем
    `AuthScreen`/`ResetPasswordScreen` напрямую, **минуя лендинг** (чтобы не
    мигал лендинг во время сброса пароля и OAuth-возврата);
  - иначе: `showAuth ? <AuthScreen onBack={…}/> : <LandingScreen onTry={…}/>`.
- Кнопки «Попробовать»/«Войти» → `setShowAuth(true)`. В `AuthScreen` добавляем
  необязательную кнопку «← назад» (`onBack` → `setShowAuth(false)`).
- Роутинг не переписываем — остаёмся на условном рендере, как сейчас (без
  react-router). Отдельные URL-маршруты — вне рамок (§9).

## 5. Анимации (технически)

- **Чистый CSS** `@keyframes` + хук `useInView` на `IntersectionObserver` —
  запуск анимации при попадании блока во вьюпорт. Без новых зависимостей
  (framer-motion не добавляем — паттерн уже есть в TelegramDemo).
- Переиспользуем `Counter` из TelegramDemo — **выносим в общий модуль**
  (`src/components/landing/` или `src/components/ui/`), чтобы не дублировать.
- `prefers-reduced-motion: reduce` — анимации упрощаем/отключаем (показываем
  финальное состояние сразу).
- Производительность: анимируем только `transform`/`opacity`; `will-change`
  аккуратно и точечно.

## 6. i18n

- Все тексты — через существующий `i18n` (`useT`/`t()`), ru по умолчанию, uk/en.
- Новые строки добавляем в `src/lib/translations.ts`.

## 7. Дизайн-визуал (последующий шаг)

- В этой итерации делаем структуру, вёрстку и анимации в коде, на существующих
  токенах темы (`--accent`, dark/light из `src/index.css`).
- Финальный визуальный лоск — опционально через **Claude Design**
  (claude.ai/design): пользователь собирает визуал, синкаем через `DesignSync`,
  затем переводим в компоненты. Это **не блокирует** первую рабочую версию.

## 8. Тестирование

- **Юнит:** хук `useInView` (мокаем `IntersectionObserver`); `Counter` (тест уже
  есть рядом); логика гейтинга `showAuth`/`?reset=1`.
- **Smoke:** лендинг рендерится при `!user`; «Попробовать» открывает `AuthScreen`;
  наличие `user` сразу минует лендинг; `?reset=1` минует лендинг.

## 9. Вне рамок (YAGNI)

- SEO / мета-теги / SSR (Vite SPA — пока не нужно).
- Отдельные URL-маршруты (react-router).
- Реальные скриншоты/видео — только анимированные мокапы.
- Аналитика, A/B-тесты лендинга.
