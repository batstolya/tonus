# Chat debug-режим «причина в скобках»

**Дата:** 2026-07-08
**Статус:** дизайн одобрен, ждёт плана
**Характер:** временный диагностический режим (~1 неделя), за env-флагом

## Проблема

AI-чат (`chat-health`) иногда выдаёт правдоподобные, но выдуманные числа
(поймали на глубине сна: сказал «июнь ~1.4 ч», реально ~0.9 ч). Нужно на неделю
включить видимость того, **на чём** модель строит ответ, чтобы отловить
оставшиеся баги: берёт ли она реальные данные через инструменты или галлюцинирует.

## Цель

Под каждым ответом чата показывать приглушённую строку в скобках с:
- **причиной** — самообъяснением модели, на каких данных построен ответ;
- **фактической трассой инструментов** — какие tool-вызовы реально произошли
  на сервере (объективный признак «взял реальные данные или нет»).

Режим включается/выключается env-флагом `CHAT_DEBUG_REASON` на функции
`chat-health`, без правок кода при откате.

## Не-цели (YAGNI)

- Никакого UI-переключателя, настроек пользователя, персистентности debug в БД.
- Не трогаем `telegram-bot` (отдельная поверхность).
- Не меняем формат хранения истории — в `chat_messages` идёт только чистый ответ.

## Архитектура

Парсинг JSON и сборка debug — **на сервере** (`chat-health`). Клиент только
рендерит пришедший `debug`, парсинга на клиенте нет.

### 1. `_shared/chatToolLoop.ts` — вернуть трассу инструментов

`ChatLoopResult` расширяется полем `toolCalls`:

```ts
export interface ChatLoopResult {
  reply: string
  totalTokens: number
  toolCalls: { name: string; args: Record<string, unknown> }[] // NEW
}
```

Петля уже итерирует `functionCalls` — накапливаем каждый `{name, args}` в массив
и возвращаем. Порядок = порядок вызова. Изменение аддитивное, существующие
потребители (`reply`, `totalTokens`) не ломаются.

### 2. `chat-health/index.ts` — промпт, парс, debug, флаг

- **Флаг:** `const DEBUG = Deno.env.get('CHAT_DEBUG_REASON') === '1'`.
- **Промпт (только при `DEBUG`):** к системному промпту добавляется инструкция:
  «Итоговый ответ верни СТРОГО как JSON без обрамления:
  `{"answer": "<ответ пользователю>", "reason": "<на каких данных построен ответ, 1-2 предложения>"}`.
  Промежуточные вызовы инструментов — как обычно.» При выключенном флаге промпт
  и поведение не меняются.
- **После `runChatLoop`:**
  - если `DEBUG` — `parseDebugReply(reply)`:
    - снять возможные ```` ```json ```` ограждения, `JSON.parse`;
    - успех → `{ answer, reason }`;
    - провал (не JSON) → `{ answer: reply, reason: '' }` (чат не падает).
  - если не `DEBUG` — `answer = reply`, debug не собирается.
  - `toolsTrace` из `toolCalls`: для каждого — `name` + компактные аргументы,
    напр. `get_sleep_range(2026-06-01..2026-06-30)`,
    `get_correlations(sleep_deep_minutes→readiness)`. Пустой массив → `[]`.
- **Сохранение:** в `chat_messages.content` пишем **`answer`** (чистый), не JSON.
- **Ответ функции:**
  ```json
  { "reply": "<answer>", "sessionId": "...",
    "debug": { "reason": "...", "tools": ["get_sleep_range(...)", ...] } }
  ```
  Поле `debug` присутствует только при `DEBUG`; иначе его нет.

### 3. Клиент — `src/lib/chat.ts` + `ChatWidget.tsx`

- `sendChatMessage` возвращает опциональный `debug?: { reason: string; tools: string[] }`.
- `ChatMessage` (локальный тип сообщения в виджете) получает опциональное
  `debug?`; заполняется только для только что полученного ответа ассистента
  (не персистится, при перезагрузке старые сообщения debug не имеют — это ок).
- `ChatWidget`: под текстом ответа, если `debug` есть, рендерит приглушённую
  строку в скобках:
  `(причина: {reason} · данные: {tools.join(', ') || 'инструменты не вызывались'})`.
  Отдельный класс (напр. `.chat-debug`) — мелкий, приглушённый цвет.
- Если `debug` не пришёл (флаг выключен) — ничего лишнего не рендерится.
  Клиентский код безопасно остаётся в проде после отключения флага.

## Обработка ошибок

- Модель вернула не-JSON при `DEBUG` → фолбэк `answer = сырой текст`,
  `reason = ''`, чат работает как раньше.
- Модель вложила markdown в `answer` → рендерится штатным `chatMarkdown`,
  `reason`/`tools` — обычным текстом.
- Инструменты не вызывались → `tools: []` → в скобках «инструменты не вызывались»
  (само по себе полезный сигнал для вопросов, требующих данных вне контекста).

## Тестирование

- **`chatToolLoop`** (unit, есть `chatToolLoop.test.ts`): петля с двумя
  tool-вызовами возвращает оба в `toolCalls` в правильном порядке; петля без
  вызовов — `toolCalls: []`.
- **`parseDebugReply`** (чистая функция, unit): валидный JSON → `{answer, reason}`;
  JSON в ```` ```json ```` ограждении → распарсен; мусор → фолбэк
  `{answer: raw, reason: ''}`.
- Форматирование `toolsTrace` (чистая функция): пример вызовов → ожидаемые
  компактные строки.
- Клиент — по конвенции проекта тесты компонентов = экспорт + покрытие переводов;
  логику форматирования скобок держать чистой функцией и тестировать напрямую.

## Деплой и откат

- Ветка `feat/chat-debug-reason` от `origin/main`.
- Задеплоить `chat-health` (`supabase functions deploy chat-health`,
  `verify_jwt` по умолчанию); выставить env `CHAT_DEBUG_REASON=1` на функции.
- Фронт — мёрдж в `main` → зелёный CI → Vercel hook.
- **Откат через неделю:** снять env `CHAT_DEBUG_REASON` (или `=0`) и передеплоить
  функцию. Сервер перестаёт просить JSON и слать `debug`; клиент при отсутствии
  `debug` ничего не рисует. Код можно удалить позже отдельным revert'ом.
