# Приватные проблемы за PIN

**Дата:** 2026-07-11 · **Статус:** approved (PIN-код на показ, только Проблемы)

## Задача

Деликатные записи (стул и т.п.) ведутся как «Проблемы» (severity 1–5,
тренд, корреляции), но их содержимое не должно быть видно постороннему,
глядящему в экран. Анализ (Исследования, AI) учитывает их полностью.

**Честная оговорка:** это защита от чужих глаз на экране, не шифрование —
данные лежат в БД и уходят в AI как обычно.

## Модель

- `health_concerns.is_private boolean not null default false`
- `profiles.privacy_pin_hash text` — SHA-256 от PIN (WebCrypto, с солью-префиксом)

## Механика (`src/lib/privacy.ts`)

- `hashPin(pin)` — SHA-256 hex от `tonus-pin:<pin>`.
- Разблокировка на сессию: флаг в `sessionStorage` (закрыл вкладку — заперто).
- `unlock(userId, pin)` — сверка с хэшем из profiles; `lock()`; `isUnlocked()`.
- `setPin(userId, newPin, currentPin?)` — смена требует текущий PIN.
- Пометить проблему приватной можно **только если PIN задан** (чекбокс в
  форме отключён с подсказкой). Правило маскировки:
  `is_private && pinSet && !isUnlocked()` — если PIN сброшен (вручную в БД),
  записи снова видимы, а не заперты навсегда.

## UI

- **Настройки**: секция «🔒 Приватность» — задать/сменить PIN,
  кнопка «Заблокировать сейчас», когда разблокировано.
- **Проблемы**: приватная карточка при запертом состоянии — «🔒 Скрытая
  запись» без имени/категории; тап → инлайн-ввод PIN → детали.
  В форме добавления — чекбокс «Приватная».
- **Исследования**: находки по приватной проблеме считаются, но вместо
  имени показывается «🔒 Скрытая проблема», пока заперто.

## Не меняется

AI-контекст (server-side), coach-profile, экспорт своих данных, RLS.

## Деплой

`supabase db push` (2 колонки) → фронт через CI. Edge-функции не трогаем.
Сброс забытого PIN — вручную в БД (обнулить `privacy_pin_hash`);
по правилу маскировки записи при этом станут видимыми — осознанный
компромисс (сброс PIN = снятие маскировки).
