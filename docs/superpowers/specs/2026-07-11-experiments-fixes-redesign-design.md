# Эксперименты: фиксы расчётов + редизайн (mate-стиль)

Дата: 2026-07-11. Статус: дизайн утверждён (макет показан и одобрен).

## Контекст и проблема

Экран «Эксперименты» (`src/components/research/ExperimentsScreen.tsx`,
вкладка Коуч → Эксперименты) работает, но:

1. **«+8.9%» вводит в заблуждение.** Данные сна в проде начинаются
   2026-06-11; у эксперимента с результатом базовая линия — всего 2 ночи.
   Порога минимального n нет: зелёный процент и d Коэна рисуются по шуму.
2. **Баг формулы `baseline_start` при создании** (строка ~276): запутанное
   выражение даёт окно **2×baseline_days**. Подтверждено в БД: у всех трёх
   строк `baseline_start = start_date − 28 дн` при `baseline_days = 14`.
   Чип «Базовый: 14 дн» показывает не то окно, по которому идёт сравнение.
3. **Латентный баг fallback** (строка ~100): при `baseline_start IS NULL`
   окно считается `daysAgo(baseline_days + 7)` — от «сегодня», а не от
   старта. Для эксперимента старше ~3 недель окно пустое.
4. **UTC-даты**: `today()`/`daysAgo()` через `toISOString()` — для UTC+3
   до 03:00 ночи «сегодня» съезжает на день назад.
5. **Замороженный `result`**: `handleAI` сохраняет снапшот расчёта в БД,
   и дальше отображается только он, даже если приехали новые данные.
6. **Ошибки ИИ глотаются**: `catch {}` в `handleAI` — пользователь не
   узнаёт, что «Объяснить (ИИ)» упало.
7. **i18n**: «слабый/средний/сильный/нет эффекта» из `effectLabel()`
   отсутствуют в `translations.ts` — в укр. интерфейсе торчит русский.
8. **UX**: master-detail (узкий список + деталь по клику) оставляет
   пол-экрана пустым; карточки «—» не объясняют причину без клика.

## Решение — часть 1: логика

Вся вычислительная логика уезжает из компонента в новый
`src/lib/experiments.ts` (чистые функции, покрытые vitest):

- `localDate(d = new Date()): string` — YYYY-MM-DD в **локальной** зоне
  (замена `toISOString().slice(0,10)`), `addDays(date, n)`.
- `computeBaselineStart(startDate, baselineDays)` = `startDate − baselineDays`
  — используется и при создании (чинит баг №2), и как fallback в расчёте
  при `baseline_start = null` (чинит баг №3).
- `computeResult(daily, exp)` — перенос текущей математики + **порог
  MIN_N = 5 в обоих окнах**: если `baselineN < 5` или `expN < 5`, результат
  считается недостоверным. Возвращаемый тип расширяется полем
  `insufficient: { window: 'baseline' | 'exp'; n: number; minN: 5 } | null`
  (для честного сообщения «мало данных: 2 из 5 ночей до старта»).
  d Коэна, дельта и % показываются только при пройденном пороге.
- `expStatusInfo`, `effectLabel`, `effectSegments`, `METRIC_OPTIONS` —
  переезжают туда же.

Поведение отображения:

- **Результат всегда считается свежим** из `daily`. Поле `experiments.result`
  в БД остаётся только как снапшот для промпта ИИ-разбора и на отображение
  не влияет (чинит баг №5).
- `handleAI`: не вызывается при `insufficient`; ошибки показываются
  текстом под кнопкой (чинит баг №6).

Миграция данных (supabase/migrations, новая миграция):

```sql
update experiments
set baseline_start = start_date - baseline_days * interval '1 day'
where baseline_start is distinct from start_date - baseline_days * interval '1 day';
```

Чинит 3 существующие строки — их базовые окна становятся заявленными
14-дневными. Деплой миграции — обычный `db push` (вне CI-пайплайна).

## Решение — часть 2: редизайн (mate-стиль)

Master-detail (`research-layout`) на этом экране убирается. Вместо него —
вертикальный дашборд, как mate.academy/home: секции с маленькими
заголовками, полноширинные светлые карточки, всё видно без кликов.
Утверждённый макет — по мокапу из обсуждения:

- **Шапка**: заголовок + подзаголовок, справа «✨ Подобрать (ИИ)»
  (secondary) и «+ Новый» (primary).
- **Секция «Идёт сейчас»** (рендерится, если есть активные): hero-карточка —
  гипотеза крупно, «Меняем: …», чипы (метрика · База: N дн · даты),
  прогресс-бар «День X из Y · результат появится после завершения».
- **Секция «Запланированные»** (если есть): компактные карточки без
  результата, бейдж «Запланирован».
- **Секция «Завершённые»**: стопка полноширинных карточек, каждая содержит:
  - гипотеза + «Меняем: …», бейдж статуса, кнопка удаления (✕);
  - чипы: метрика · База: N дн · даты;
  - при достаточных данных — строка результата **До → Во время →
    Изменение**: три ячейки с крупными числами, n под каждой, ячейка
    «Изменение» тонирована (зелёный = улучшение с учётом betterHigh,
    красный = ухудшение, серый = без изменений);
  - строка «Размер эффекта d = … · слабый/средний/сильный» + шкала
    из 4 сегментов;
  - оговорка «Наблюдение, не доказательство» + кнопка «Объяснить
    результат (ИИ)»; готовый разбор — раскрывающийся блок в карточке;
  - при `insufficient` — серое состояние с причиной: «Мало данных:
    X из 5 ночей в базовом периоде. Данные начинаются DD.MM — …»
    (без результата и без кнопки ИИ). Никаких голых «—».
- **ИИ-предложения** («Подобрать») и **форма создания** остаются
  функционально как есть, оформляются такими же карточками.
- **Пустое состояние** — как сейчас (🧪 + приглашение), стиль подгоняется.

Визуальный язык: существующие токены (`--surface*`, `--border`, радиусы,
caps-подписи секций как в mate-style панели стрика), обе темы. Мобилка:
тройка результата переносится (как текущий `@media 540px`), карточки в
столбик. Motion не добавляем (экран без анимаций, как TelegramDemo).

## Вне охвата

- Остальные вкладки «Коуч» (Инсайты/Исследования/Цели) — отдельной спекой.
- Edge-функции `suggest-experiments`, `deep-research` — не трогаем.
- Серверный расчёт результатов, изменения схемы БД (кроме data-миграции).

## Тесты

- `src/lib/experiments.test.ts`: окна baseline/exp (границы включения),
  `computeBaselineStart`, fallback при null, порог MIN_N (оба окна),
  `insufficient` с правильным окном и n, знак/направление для
  betterHigh/betterLow, `localDate`/`addDays` (в т.ч. смена месяца).
- Тест переводов новых строк по паттерну `TelegramDemo.test.ts`
  (+ добавить недостающие «слабый/средний/сильный/нет эффекта»).
- Существующий рендер-паттерн: компонент остаётся тонким, экспорт
  проверяется как обычно; e2e не трогаем.

## Критерии приёмки

1. В БД `baseline_start = start_date − baseline_days` у всех строк,
   новые создаются с правильным окном; чип «База: N дн» соответствует
   фактическому окну сравнения.
2. Результат и d показываются только при n ≥ 5 в обоих окнах; иначе —
   объясняющее состояние с числами «X из 5».
3. Экран — секционный дашборд по утверждённому макету, без master-detail,
   в обеих темах, адаптивный.
4. Все новые строки переведены (uk/en), включая метки размера эффекта.
5. `npm test`, `npm run build` зелёные; lint без новых ошибок.
