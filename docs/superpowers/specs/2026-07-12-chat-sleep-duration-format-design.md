# Формат длительности сна в ИИ-чате

## Проблема

`get_sleep_range` передаёт Gemini длительности сна как десятичные часы. Поэтому
модель показывает `1.67 години`, хотя интерфейс приложения для того же значения
показывает человекочитаемую длительность: `1 год 40 хв`.

## Решение

В общей серверной логике chat tools добавить чистый форматтер длительности из
десятичных часов в украинскую строку `N год M хв`. Значение округляется до
ближайшей целой минуты. Нулевые часы или минуты не выводятся, кроме полного нуля
(`0 хв`).

Для результата `get_sleep_range`:

- сохранить числовые поля `duration_hours`, `deep_hours`, `rem_hours` и
  `core_hours`, чтобы модель могла сравнивать значения;
- добавить к каждой строке display-поля для тех же длительностей;
- добавить display-строку к каждому серверному среднему;
- уточнить описание инструмента: в пользовательском ответе показывать
  display-поля, а числовые значения использовать только для анализа.

Формат применяется ко всем длительностям сна: общему, глубокому, REM и
основному сну. Другие метрики и UI не меняются.

## Граничные случаи

- `1.67` → `1 год 40 хв`;
- `1.03` → `1 год 2 хв`;
- `0.8` → `48 хв`;
- `2` → `2 год`;
- `null`, `undefined`, `NaN` не получают display-значение.

Если округление минут даёт 60, значение переносится в следующий целый час.

## Проверка

Сначала добавить падающие Vitest-тесты на форматтер и структуру результата
`get_sleep_range`. Затем реализовать минимальную логику и запустить целевой
тестовый файл, после чего — полный `npm test`.
