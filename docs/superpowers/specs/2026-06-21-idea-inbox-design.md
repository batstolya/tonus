# Личный «ящик идей» через Telegram-бота — дизайн

**Дата:** 2026-06-21
**Объём:** маленькая фича. Пишу боту идею — она сохраняется приватно (не видна на сайте), чтобы не забывать.

## Поведение

- **`/idea <текст>`** — сохраняет идею, отвечает «💡 Записал. Все идеи — /ideas». Пустой `/idea` без текста → подсказка с примером.
- **`/ideas`** — присылает пронумерованный список последних идей (до 50) с датами. Пусто → «Идей пока нет».
- Обе команды зарегистрированы в `setMyCommands` (автокомплит по `/`).

## Хранилище

Отдельная таблица `public.ideas` (не переиспользуем `context_notes`/`intake_events` — другое назначение):

```sql
ideas: id uuid pk, user_id uuid → auth.users on delete cascade, text text not null, created_at timestamptz default now()
```

RLS «свой видит/пишет своё». **Нигде на сайте не отображается** — ни один экран её не запрашивает. Бот пишет через service-role, `user_id` — из `telegram_links` по `telegram_chat_id`.

## Маршрутизация в боте

Хэндлеры `/idea` и `/ideas` врезаются в текстовый роутер `supabase/functions/telegram-bot/index.ts` **до** фолбэка неизвестных команд (`if (text.startsWith('/'))`) и до `looksLikeLog`/ИИ-чата — так чат и логирование еды не затрагиваются. `/ideas` матчится точным равенством, `/idea` — `=== '/idea' || startsWith('/idea ')`, коллизии между ними нет.

Список и подтверждения шлются **простым текстом** (без `parse_mode`) — текст идеи произвольный, так нет риска битого HTML/ошибки 400.

## Не в объёме (YAGNI)

Отметки готово/удалить, теги, ИИ-обработка, кнопки у пунктов, показ на сайте, поиск. Чистый «записал / прочитал список».

## Проверка

- Миграция применена, колонки/таблица есть.
- `/idea тест идея` → строка в `ideas`; `/ideas` → показывает её с датой; пустой `/idea` → подсказка.
- Деплой бота: `verify_jwt` остаётся false (config.toml), webhook жив.

## Файлы

- `supabase/ideas.sql` (новый) — миграция.
- `supabase/functions/telegram-bot/index.ts` — `setupCommands` (+2 команды), `/idea` и `/ideas` хэндлеры.
