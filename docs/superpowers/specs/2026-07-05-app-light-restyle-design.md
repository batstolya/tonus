# Приложение: рестайл светлой темы (mate-стиль) + light по умолчанию

Дата: 2026-07-05. Статус: утверждено пользователем (дефолт light везде, стилевой слой без редизайна лейаутов, тёмную тему не трогаем).

Продолжение `2026-07-05-landing-light-theme-hiw-fix-design.md` (лендинг уже в mate-стиле, PR #4 задеплоен).

## Цели

1. Светлая тема внутренних экранов — в едином mate-стиле с лендингом: белые карточки с мягкими тенями, светло-серый фон, жирная типографика, мягкие радиусы.
2. Light — тема по умолчанию везде (лендинг и приложение). Явный выбор пользователя в localStorage побеждает, как и сейчас.
3. Починить артефакты текущей светлой темы (тёмные хардкоды, ломающиеся на белом).

## Не входит

- Тёмная тема приложения: без визуальных изменений, кроме общих правок типографики/радиусов (утверждено).
- Редизайн лейаутов экранов: разметка, навигация, состав компонентов не меняются.
- Распил `index.css` на файлы по фичам, дизайн-токен-система, новые шрифты.
- Лендинг (уже сделан).

## Архитектура

Всё через существующий механизм: значения в блоке `[data-theme="light"]` в `src/index.css` + light-scoped переопределения компонентов. Приложение уже использует `var(--*)` в ~95% правил (527 использований, 42 хардкода, из них проблемных 2).

### 1. Дефолт темы

`src/App.tsx`: `useTheme(user ? 'dark' : 'light')` → `useTheme('light')`. Логика `resolveTheme` (сохранённый выбор побеждает) не меняется; существующие пользователи с сохранённой темой ничего не заметят. Тест-контракт `resolveTheme` уже есть (`src/hooks/useTheme.test.ts`).

### 2. Токены light (index.css `[data-theme="light"]`)

- `--bg: #f6f6f9` (было `#f2f2f7`) — очень светлый фон, на котором читаются белые карточки; чисто белый не подходит (карточки сольются).
- `--border: #ececf2` (было `#e0e0e8`) — бордеры почти невидимы, разделение берут на себя тени.
- Новый токен `--card-shadow`: в light `0 4px 16px rgba(17, 17, 24, 0.06)`, в `:root` (dark) `none`.
- Остальные токены light (`--surface: #fff`, `--accent: #4a6fff`, semantic-цвета) не меняются.

### 3. Общие правки (обе темы, утверждено)

- `--radius: 12px → 14px` в `:root`.
- Заголовки экранов: `.screen h2` — `font-weight: 800; letter-spacing: -0.5px` (сейчас 700). Заголовок дашборда и `block-title`-аналоги внутри приложения — так же (точный список по факту аудита).
- Primary-кнопки (`.landing-cta`-аналоги внутри: `.btn-primary` и активные пресеты) — радиус 12px, если сейчас меньше.

### 4. Карточки в light

Light-scoped правило для карточных классов: тень `var(--card-shadow)`, hover — тень глубже вместо (или вместе с) accent-бордера. Ядро списка (дополняется аудитом в плане):

- `.metric-card` (+ hover: тень `0 8px 24px rgba(17,17,24,0.10)`, бордер остаётся accent)
- контейнеры дашборда: readiness-карта, quick log, инсайты, коуч-карточка, data-gaps
- секции экранов: settings-секции, supplements/labs/goals/experiments-карточки, chat-окно

Реализация — общим списком селекторов в одном light-блоке, не размазывая по файлу.

### 5. Фиксы текущих багов light

- `index.css:202` `.upload-zone:hover` — `background: #1e2235` (тёмный хардкод) → `color-mix(in srgb, var(--accent) 8%, var(--surface))`.
- `index.css:227` `.error-msg` — `background: #2a1a1a` → `color-mix(in srgb, var(--red) 12%, var(--surface))`.
- Аудит остальных 40 хардкодов: `#fff` на accent-фоне и semantic-константы (`#f59e0b`, `#d97706`, `#4285F4`, app-loader) — валидны в обеих темах, не трогаем; всё, что выглядит сломанным на экранах при проходе, чинится тем же паттерном color-mix.

### 6. Пастель — сдержанно

Существующие тонированные блоки (readiness, стресс-карточки, caffeine-bar, data-gaps) уже пастельные — только проверить контраст на новом фоне. Новые пастельные подложки не добавляем.

## Приёмка

- Свежий пользователь (пустой localStorage): лендинг и приложение открываются в light; тумблер в приложении работает как раньше; сохранённый dark-выбор уважается.
- Все экраны навигации в демо-режиме (Dashboard, Body: метрики/сон/пульс/стресс/волосы/анализы, Journal: приёмы/питание/добавки/цели/эксперименты, Coach, Research, Settings, Chat) в light: белые карточки с тенями, читаемый контраст, ни одного тёмного артефакта.
- Тёмная тема: визуально без изменений, кроме радиусов и веса заголовков.
- Мобильная ширина 375px: light-экраны без слома.
- `npm test`, `npm run build` зелёные; `npx eslint` изменённых файлов без новых ошибок.

## Тестирование

- Существующие тесты (107) остаются зелёными; `resolveTheme` уже покрыт.
- Новых модулей не появляется → новых unit-тестов не требуется; верификация визуальная через демо-режим в превью (обе темы, десктоп + мобилка).

## Риски

- 1767-строчный `index.css`: light-переопределения держим одним блоком в конце файла (как в Landing.css), чтобы не расползлись.
- Смена `--radius` затрагивает обе темы во всех местах с `var(--radius)` — проверить dark контрольным проходом.
- Классы, найденные аудитом сверх ядра списка карточек, чинятся в рамках задачи аудита — это ожидаемая часть работы, не расширение скоупа.
