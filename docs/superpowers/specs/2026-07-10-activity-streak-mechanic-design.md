# Стрік = трекер звички, а не аптайм синку

**Дата:** 2026-07-10
**Статус:** затверджено користувачем (4 рішення зафіксовані в чаті)

## Проблема

«Активний день» зараз = «прийшла хоч одна метрика» (`isActiveDay` в
`src/lib/streak.ts`). З автосинком через HAE стрік росте сам, поки працює
техніка: метрика вимірює здоров'я пайплайна, а не людини.

## Рішення

### 1. Новий предикат активного дня (з cutoff-датою)

```
ACTIVE_STEPS_MIN = 7000      // кроків
ACTIVE_EXERCISE_MIN = 30     // хвилин exerciseMinutes (зелене кільце Apple)
ACTIVITY_RULE_SINCE = '2026-07-10'
```

- `date < ACTIVITY_RULE_SINCE` → старе правило: є будь-яка core-метрика
  (кроки/сон/пульс/HRV). Історія і поточний стрік 450 днів не переписуються.
- `date >= ACTIVITY_RULE_SINCE` → активний, якщо
  `steps >= 7000 || exerciseMinutes >= 30`.
- Обидві метрики вже синкаються з Apple Health — нових даних не треба.
- Пороги — іменовані константи. Персональні налаштування — свідомо потім
  (YAGNI); спека фіксує, що константи мають бути єдиним місцем правки.

Новий допоміжний предикат `hasDayData(d)` — «прийшла хоч одна core-метрика»
(стара семантика isActiveDay), потрібен календарю і рядку прогресу.

Через спільний предикат автоматично переходять на нове правило: стрік днів,
заморозки, тижневий стрік (⚡), тижневий рекорд, «Активні дні · місяць»,
чекмарки тижнів у календарі.

### 2. Календар — три стани минулих днів

| Стан | Умова | Вигляд |
|---|---|---|
| `active` | поріг закритий (або старе правило до cutoff) | зелений залитий |
| `frozen` | закритий заморозкою | ❄️ |
| `idle` | дані є, поріг не закритий | сірий залитий (як зараз missed) |
| `missed` | даних нема | контур 1px, бліда цифра |
| `future` | майбутнє | бліда цифра без контуру |

До cutoff стан `idle` не виникає (будь-який день з даними = active) —
природно виходить з предиката.

### 3. Прогрес дня в панелі

Рядок під шапкою панелі (замість/поруч з «Синхронізація очікується»):

- Сьогодні даних нема взагалі (`!hasDayData`) → «Синхронізація очікується»
  (як зараз).
- Дані є, поріг не закритий → «Сьогодні: 4 200 / 7 000 · 12 / 30 хв»
  + міні прогрес-бар по кращому з двох відношень
  (`max(steps/7000, exercise/30)`).
- Поріг закритий → рядок не показується.

`todayPending` в `computeStreak` вже дає грейс до кінця дня — семантика
не змінюється.

### 4. Що НЕ змінюється

- Механіка заморозок (1 за 7 днів, кап 3) — тепер вони рятують ліниві дні;
  подивимось по факту, чи треба пом'якшувати.
- Тригер у топбарі (🔥 N) — без прогресу дня, мінімалізм.
- Банер staleness — він і так на `ingest_tokens`, не на предикаті.

## Тести

- Предикат: до cutoff день з даними активний; після cutoff 5000 кроків — ні,
  7000 — так, 29 хв — ні, 30 хв — так, «кроки мало АЛЕ вправи є» — так.
- Існуючі тести стріку використовують `steps: 5000` на датах після cutoff —
  підняти фікстури до значень вище порогу (інакше вони тепер неактивні).
- Календар: перевірка нових станів через переклади/експорт (node env).
- Прогрес дня: чиста функція обчислення прогресу — юніт-тести.
