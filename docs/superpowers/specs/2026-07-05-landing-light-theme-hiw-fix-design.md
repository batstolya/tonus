# Лендинг: светлая тема (mate-стиль) + фикс шагов «Как это работает»

Дата: 2026-07-05. Статус: утверждено пользователем (охват, дефолт, глубина — выбраны рекомендованные варианты).

## Цели

1. Починить баг секции «Как это работает»: при скролле активный шаг не переключается, подсвечен только один.
2. Светлая тема лендинга в духе mate.academy: белый фон, крупная тёмная типографика, карточки с мягкими тенями, пастельные акценты. Светлая — по умолчанию для новых посетителей.
3. Тёмная тема лендинга сохраняется без визуальных изменений и доступна по тумблеру.

## Не входит (отдельные спеки потом)

- Рестайл внутренних экранов приложения под mate-стиль (следующий заход после утверждения стиля на лендинге).
- Изменение структуры/контента лендинга: набор и порядок блоков (Hero, TrustStrip, HowItWorks, Chat, Telegram, FeatureGrid, FinalCta) не меняется.
- Новые шрифты: остаёмся на системном стеке (`--font`). Подключение Manrope/Inter — опционально отдельным решением.
- Смена дефолтной темы внутри приложения (остаётся dark).

## Часть 1. Фикс HowItWorks

### Причина бага

`src/components/landing/blocks/HowItWorks.tsx`: каждый `StepText` использует `useInView({ threshold: 0.6, once: false })` и вызывает `onActive(index)` при появлении во вьюпорте. Колонка из трёх шагов (~700px) на десктопе помещается в экран целиком: все три становятся «видимыми» почти одновременно и больше не покидают вьюпорт → IntersectionObserver перестаёт генерировать события → активный шаг залипает.

### Решение: центральная полоса

Шаг активен, когда пересекает узкую горизонтальную полосу в центре вьюпорта:

- `useInView` (`src/components/landing/useInView.ts`) получает опцию `rootMargin?: string`, прокидываемую в IntersectionObserver.
- `StepText` использует `{ rootMargin: '-45% 0px -45% 0px', threshold: 0, once: false }` — полоса в 10% высоты экрана по центру. В неё практически всегда попадает не больше одного шага.
- Пока ни один шаг не дошёл до центра, активен шаг 0 (текущее initial state, не меняется).
- `immediatelyVisible()`-деградация (нет IO / prefers-reduced-motion) не меняется: все шаги видимы (opacity 1 в reduce-media), sticky-сцена показывает шаг 0.
- Мобильная версия (< 860px) не затрагивается: sticky-сцена скрыта, inline-сцены в каждом шаге.

Альтернативы, отклонены: scroll-листенер с выбором ближайшего к центру шага (больше кода, ручной throttling); `useScroll` из Motion (scroll-linked прогресс → индекс; лишняя связанность с layout-высотами).

### Приёмка (часть 1)

- Десктоп ≥ 860px, обе темы: скролл через секцию последовательно подсвечивает шаги 1 → 2 → 3, сцена справа переключается с анимацией; обратный скролл — 3 → 2 → 1.
- Высокий вьюпорт (все шаги видны сразу): переключение всё равно работает.
- `prefers-reduced-motion`: все шаги полной непрозрачности, ничего не мигает.

## Часть 2. Светлая тема лендинга

### Поведение темы по умолчанию

- Нет сохранённой темы в `localStorage` **и** пользователь не залогинен (лендинг/auth) → `light`.
- Нет сохранённой темы, пользователь залогинен → `dark` (как сейчас).
- Явный выбор тумблером сохраняется в `localStorage.theme` и побеждает везде (лендинг и приложение). Существующие пользователи с сохранённым выбором ничего не заметят.
- Реализация: `useTheme` принимает дефолт (или резолвер); App передаёт его в зависимости от наличия сессии. Тумблер и текущая тема пробрасываются в `LandingScreen` пропсами (не второй экземпляр хука).
- В топбар лендинга добавляется кнопка-тумблер ☀️/🌙 рядом с переключателем языка.

### Визуальный язык light (mate-стиль)

Всё реализуется в `Landing.css` блоком переопределений `[data-theme="light"] .landing …` поверх существующих CSS-переменных; тёмная тема не трогается.

- **Фон:** чистый белый — `.landing` локально переопределяет `--bg: #ffffff` (в приложении light остаётся `#f2f2f7`). Фоновая сетка `lp-bg::before` остаётся (она через `--text`, на белом даёт лёгкую серую сетку).
- **Glow-пятна:** пастельные и слабее (opacity ≈ 0.10, светлые тона акцента/сирени), без «неона».
- **Карточки (`lp-glass`):** вместо стекла — белые карты: непрозрачный `#fff`, бордер `--border`, мягкая тень (`0 8px 30px rgba(17,17,24,0.08)`), радиус 16–20px, без backdrop-filter. Hover — лёгкий подъём тени вместо неонового свечения.
- **Кнопки:** CTA остаётся `--accent` (#4a6fff) с белым текстом; радиус 12px, hover-лифт. `landing-ghost` — бордерная светлая.
- **FeatureGrid:** карточки получают пастельные подложки (4 тона: лаванда, мята, персик, лимон — низкой насыщенности, тёмный текст). В тёмной теме — без изменений. Реализация: локальные переменные `--lp-pastel-1..4`, применяются только в light.
- **Типографика:** заголовки weight 800, letter-spacing до −1.5px, hero-заголовок крупнее (clamp верх ~56px). Меняется в базовых правилах лендинга (влияет на обе темы — в тёмной это тоже улучшение, не регресс).
- **Градиентный текст (`lp-grad-text`), сцены HowItWorks, чат, телефон Telegram, LiveDemoPanel:** проходят через переменные — аудит каждого блока в светлой теме, точечные фиксы контраста (особенно `color-mix(... transparent)` поверх белого фона и `tg-phone-screen` с `--bg`).
- **Топбар:** белый полупрозрачный при скролле (`--topbar-bg` light уже есть), тонкий нижний бордер.

### Приёмка (часть 2)

- Инкогнито-заход на лендинг → светлая тема; тумблер переключает и запоминает; после логина без явного выбора приложение остаётся в dark.
- Все 7 блоков лендинга в light: контраст текста читаемый, ни одного «тёмного островка» или невидимого элемента; в dark — попиксельно прежний вид (кроме утверждённых типографических правок).
- Мобильная ширина 375px в обеих темах без слома вёрстки.

## Тестирование и верификация

- `npm test` (Node 24): существующий паттерн — тесты экспортов/переводов; при изменении `useInView` — юнит на новую опцию, если выделима чистая логика; иначе ручная верификация.
- Ручная верификация в превью (VITE_DEMO не нужен, лендинг статичный, dummy `.env.local`): скролл HowItWorks в обеих темах, скриншоты light/dark десктоп + мобайл.
- `npm run build` и `npm run lint` — без новых ошибок.

## Риски

- `color-mix(... transparent)`-подложки, рассчитанные на тёмный фон, могут «пропасть» на белом — закрыто пунктом аудита всех блоков.
- Двойное управление `data-theme` (App + логика дефолта) — исключаем, оставляя единственный вызов `useTheme` в App и пробрасывая пропсы.
- Утверждённые типографические правки затрагивают и тёмную тему — принято осознанно (см. «Визуальный язык»).
