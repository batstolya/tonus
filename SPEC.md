# Tonus — техническое задание

**Платформа:** локальное веб-приложение (браузер), React + TypeScript
**Источник данных:** загрузка файлов экспорта Apple Health и календаря (.ics)
**Версия документа:** 2.0
**Главный принцип:** всё считается в браузере, данные никуда не загружаются.

---

## 1. Краткое описание

Tonus — локальное веб-приложение, которое принимает выгрузку Apple Health (архив с `export.xml`) и, по желанию, файл календаря (`.ics`), и превращает их в понятные выводы о состоянии пользователя. Весь разбор и анализ происходят в браузере; серверной части нет.

Флагманская функция — **карта стресса**: сопоставление пульса с событиями календаря, чтобы видеть, какие встречи и ситуации сильнее всего влияют на сердце.

## 2. Цель и ключевая ценность

Пользователь, загрузив файлы, должен унести один понятный вывод о себе, а не массив цифр.

- Понятная картина состояния за период (пульс, восстановление, активность) в виде графиков, а не строк.
- Тренды и простые инсайты на естественном языке («пульс покоя за неделю вырос на 4 удара»).
- Связь физиологии с реальной жизнью — какие события дают наибольшую нагрузку на сердце.

Чего приложение НЕ делает: не ставит диагнозов и не претендует на доказанные причинно-следственные связи. Все взаимосвязи — наблюдения и подсказки.

## 3. Ключевые архитектурные решения

- **Источник данных — файлы, разбор в браузере.** Пользователь загружает архив/`export.xml`; карта стресса дополнительно использует `.ics`. Никакого HealthKit и live-доступа.
- **Полностью локально, без сервера.** Загруженные файлы и вычисления остаются в браузере и никуда не передаются.
- **Никаких аккаунтов, плат и публикации в сторах.** Приложение открывается как обычная страница (локально или на статическом хостинге).

### Технологический стек

- **UI:** React + TypeScript (Vite).
- **Разбор большого `export.xml`:** потоковый (SAX-подобный) парсер в **Web Worker**, чтобы интерфейс не подвисал на файле в сотни МБ. Не держать весь файл в памяти одной строкой.
- **Распаковка архива:** разбор `.zip` в браузере (например, JSZip), чтобы принимать выгрузку как есть.
- **Календарь:** парсер `.ics` на клиенте.
- **Графики:** библиотека визуализации для React (например, Recharts).
- **Кэш (опционально):** IndexedDB, чтобы не разбирать большой файл при каждом открытии. Только на устройстве пользователя.

## 4. Экраны и функции

### 4.1. Загрузка данных
Зона drag-and-drop для архива/файла Apple Health (`export.zip` или `export.xml`) и отдельная зона для `.ics` (опционально). Индикатор прогресса; для большого XML разбор в фоне. Явное сообщение, что файлы не уходят на сервер. Понятная ошибка при неверном формате. Возможность загрузить новые файлы и пересчитать без перезагрузки.

### 4.2. Главный экран (дашборд)
Сводка за последний доступный период: ключевые показатели крупными карточками, 1–2 заметных инсайта, переходы в разделы ниже.

### 4.3. Пульс за период
Выбор диапазона дат (пресеты день / неделя / месяц + произвольный). На выходе:
- График пульса по времени; для длинных периодов — агрегация по дням (мин/средний/макс).
- Сводные цифры: средний пульс, пульс покоя, максимум, время в зонах нагрузки.
- Наведение на точку показывает точное время и значение.

### 4.4. Все показатели — сводная таблица
Объединённая таблица «день × показатель»: одна строка — день, столбцы — показатели. Вместо голого CSV — интерактивные графики и возможность наложить два показателя (например, пульс покоя и HRV).

### 4.5. Карта стресса — пульс ↔ календарь (флагман)
События из загруженного `.ics` сопоставляются с пульсом в те же интервалы.
- Список событий, отсортированных по «нагрузке на сердце» (средний и пиковый пульс за время события).
- Сравнение с личным базовым уровнем (пульс покоя в это время дня), а не с абсолютной планкой.
- События во время физической активности помечаются отдельно (спорт ≠ эмоции).
- На коротких интервалах и редких замерах — формулировка «сердце реагировало сильнее», без громких утверждений про «тревожность».

### 4.6. Инсайты и тренды
Простые правила: динамика пульса покоя и HRV по неделям, связь активности и восстановления, аномальные дни. Каждый инсайт с мини-графиком и оговоркой «это наблюдение, не диагноз».

### 4.7. Экспорт
Выгрузка сводки за период в CSV или PDF. Файл формируется в браузере по инициативе пользователя.

## 5. Показатели из `export.xml`

Берутся из записей `<Record type="HKQuantityTypeIdentifier...">`. Колонка «Агрегация» — как сводить за день.

| Показатель | Тип записи (после префикса HK…Identifier) | Агрегация за день |
|---|---|---|
| Пульс | HeartRate | среднее, мин, макс |
| Пульс покоя | RestingHeartRate | значение за день |
| Вариабельность пульса (HRV) | HeartRateVariabilitySDNN | среднее |
| Пульс при ходьбе | WalkingHeartRateAverage | среднее |
| Кислород в крови (SpO₂) | OxygenSaturation | среднее |
| Частота дыхания | RespiratoryRate | среднее |
| Температура запястья (сон) | AppleSleepingWristTemperature | значение |
| VO₂max | VO2Max | значение |
| Сон | SleepAnalysis (категория) | сумма длительностей фаз |
| Шаги | StepCount | сумма |
| Дистанция | DistanceWalkingRunning | сумма |
| Активная энергия | ActiveEnergyBurned | сумма |
| Минуты тренировки | AppleExerciseTime | сумма |
| Этажи | FlightsClimbed | сумма |

Набор показателей зависит от того, что записали часы; отображать те, по которым в файле есть данные.

## 6. Особые случаи (важно для реализации)

- **Большой файл.** `export.xml` — сотни МБ. Потоковый разбор в Web Worker, с прогрессом, без загрузки всего файла в память как одной строки.
- **Повторная загрузка.** Желательно кэшировать разобранные данные (IndexedDB), кэш — только в браузере.
- **Сон.** Хранится интервалами с фазами; длительность за ночь = сумма интервалов, привязанная к дате пробуждения, а не к календарной полуночи.
- **Дубли источников.** Шаги/энергия пишутся и iPhone, и часами. Отдавать приоритет одному источнику (часам) или дедуплицировать, чтобы не задвоить суммы.
- **Часовые пояса.** Записи `export.xml` содержат смещение пояса; события `.ics` — свои метки. Приводить к согласованному локальному времени, чтобы слоты встреч и пульс совпадали.
- **Пустые периоды и редкие замеры.** Если данных мало или нет — явно сообщать. Не строить выводы на 2–3 точках.

## 7. Приватность

- Все вычисления и хранение — в браузере; файлы не передаются на сервер или третьим лицам.
- Нет аккаунтов и сбора персональных данных.
- При публичном хостинге — короткое пояснение, что обработка локальная.

## 8. Нефункциональные требования

- Производительность: плавный разбор файлов в сотни МБ; тяжёлые операции — в Web Worker.
- Офлайн: после открытия страница работает без интернета (можно оформить как PWA).
- Кроссбраузерность: актуальные Chrome, Safari, Firefox, Edge.
- Доступность: адаптивная вёрстка, читаемость, тёмная тема.

## 9. Этапы

- **MVP (v1):** загрузка `export.xml`/`.zip` с разбором в браузере; «Пульс за период» с графиком; сводная таблица «Все показатели»; карта стресса по `.ics`; базовые инсайты; экспорт CSV/PDF.
- **v2:** кэш (IndexedDB); углублённые инсайты; детальный раздел сна; оформление как PWA.
- **v3:** сравнение периодов; отчёт «для врача»; ручной ввод/правка событий как дополнение к `.ics`; опциональная упаковка в десктоп (Tauri/Electron).

## 10. Рекомендуемый порядок реализации

1. Каркас: загрузка файла + разбор `export.xml` в Web Worker + извлечение пульса. **Это самая сложная часть (большой файл) — делать первой.**
2. Экран «Пульс за период» с графиком на реальных данных.
3. Сводная таблица «Все показатели».
4. Карта стресса (разбор `.ics` + сопоставление с пульсом).
5. Инсайты, экспорт, полировка.
